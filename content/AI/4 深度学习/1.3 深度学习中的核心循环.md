## 1.1 数据加载

### 1.1.1 `multi_dataset_loader`

#### 函数作用

负责从多个数据源（不同的数据集）分别取一批数据，然后把它们拼接成一个大的 batch 返回给模型训练
#### 函数流程

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                       multi_dataset_loader() 做什么？                        │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│   ┌─────────────────┐                                                        │
│   │  主数据加载器    │ → 取 batch_0 张图 → 预处理 → ┐                        │
│   └─────────────────┘                              │                        │
│   ┌─────────────────┐                              │                        │
│   │  人脸数据加载器  │ → 取 batch_1 张图 → 预处理 →  ├→ 所有数据拼在一起      │
│   └─────────────────┘                              │   返回给模型训练       │
│   ┌─────────────────┐                              │                        │
│   │  色彩数据加载器  │ → 取 batch_2 张图 → 预处理 → ┘                        │
│   └─────────────────┘                                                        │
│   ┌─────────────────┐                                                        │
│   │  静态数据加载器  │ → 取 batch_3 张图 → 预处理                            │
│   └─────────────────┘                                                        │
│   ┌─────────────────┐                                                        │

│                                                                              │
│   最后 sample['input'] 可能从原来的 N 张图 → 变成 N×5 张图                   │
│   因为每个数据源都贡献了一批数据                                             │
│                                                                              │
└──────────────────────────────────────────────────────────────────────────────┘
```


#### 设计
| 为什么要多个数据源？ | 解释                               |
| ---------- | -------------------------------- |
| **主数据**    | 主体数据集，模型主要在这里学习去噪                |
| **人脸数据**   | 人脸区域纹理敏感，单独加数据可以让模型对人脸去噪效果更好     |
| **色彩数据**   | 某些场景颜色噪声明显，需要额外学习                |
| **静态数据**   | 针对静态场景（如风景照），帮助模型学会保留细节          |
| **问题数据**   | 专门放一些难样本（极端亮度、特殊噪声），让模型学会处理“坏例子” |

**本质**：一个数据集可能覆盖不全，多数据集混合可以让模型在**更多样化的数据上训练**，提高泛化能力。

### 1.1.2 模型的额外输入（为什么除了x和y_true, 还需要给模型其他输入参数？）

**从数学上讲，给定足够多的数据 (x, y_true)，一个足够大的神经网络绝对可以作为一个“黑盒”，自己学会从像素值推断噪声强度，然后输出去噪图。这是 Universal Approximation Theorem（万能近似定理）保证的。**
那么问题来了：**“既然它能自己学会，为什么还要强行喂它 k 和 b？”**
这不是因为“它做不到”，而是因为**“工业界不想让它把所有精力都花在‘猜’这件事上”**。这里有几个非常现实的原因：
#### 1. 核心原因：为了“省参数”和“省计算量”
- **盲猜（只给 x）**：网络必须用第一层卷积去算“这个像素亮度是多少”，用第二层去算“周围像素亮度差异”，用第三层去算“这个亮度对应的方差大概是多少”……为了算出这个“亮度->噪声”的物理公式，网络需要**浪费掉几十万个神经元**来拟合那条简单的直线（方差 = k*亮度 + b）。
- **开卷（给 k/b）**：既然我们已经用数学公式算好了，直接塞给它。网络就**不需要用卷积层去模拟数学公式**了。省下来的神经元，可以全部用来干真正的脏活累活——**区分“噪声”和“真实纹理”**。

> **类比**：让一个厨师做西红柿炒蛋。
> - **只给 x**：你必须自己尝味道（猜盐放了多少），自己判断火候，这很费脑子，容易翻车。
> - **给 x + k/b**：我直接告诉你“这勺盐是5克”（即 k 参数），你就不用费劲去尝了，直接专注在“怎么翻炒不让鸡蛋变老”上（去噪保留纹理）。

#### 2. 核心原因：应对“没见过的场景”（泛化能力）
黑盒模型最大的痛点是**“死记硬背”**。
- 如果训练集里，**“亮度值=100”** 对应的噪声都是 **方差=10**。
- 模型学死了：“亮度=100，我就要减掉10的噪声”。
- **上线后**：换成了一颗新Sensor，或者调高了ISO，导致“亮度值=100”对应的噪声变成了 **方差=50**。
- 模型一看：“不对啊，我没学过这个！” 它就会**强行按照“方差=10”去去噪**，结果就是去不干净（残留大量噪声）。

**如果你喂了 k/b 呢？**  
模型学到的逻辑就变了，它不再看“亮度是多少”，而是看“`k` 是多少”。
- 当新Sensor传来 `k=50`（表示噪声大），模型虽然没见过这个Sensor，但它见过 `k=50` 的训练数据。**它不需要认识新Sensor，它只需要看懂 k 这个数字。**
- 这就是 **“模型迁移”**——只要噪声参数标定得准，模型可以轻松适配任何新Sensor，不需要重新训练。

#### 总结
可以把 k/b 理解为**“辅助损失函数的先验知识”**。
- 如果算力无限、数据无限，只给 x 确实能达到完美的效果（学术界很多论文就是这么干的）。
- 但在**工业界（AI ISP）**，算力有限（要在NPU上跑），数据有限（不可能覆盖所有ISO、所有Sensor）。**我们把物理公式（泊松-高斯模型）的结果直接塞给网络，是工程师为了“省参数、提速度、保迁移”所做的妥协和智慧。**
一句话杀死比赛：**网络确实能学会 1+1=2，但既然你都已经把 `2` 写在纸条上给网络了，网络就能把算力省下来去解决微积分（纹理恢复）了。** 这就是 AI ISP 实战和纯学术研究最大的区别。

### 1.1.3 噪声参数 kmap与bmap
`kmap` 和 `bmap` 是这个去噪模型中**极其关键**的输入，它们代表**噪声模型的参数图**。
简单来说，它们是用来告诉模型：“**这张图的哪个位置噪声有多大、是什么类型的噪声**”。

#### 1.1.3.1 物理源头：真实 Sensor 的噪声不是“均匀”的
在相机 Sensor（CMOS）中，噪声主要由两个部分构成：
1. **光子散粒噪声（Shot Noise）**：光本身是粒子（光子），到达 Sensor 的数量是随机的。**光线越亮，光子随机波动越大，噪声就越大。**
2. **读出噪声（Read Noise）**：Sensor 电路本身产生的电噪声（热噪声等）。**这个噪声基本是固定的，不随亮度变化。**

在工程上，为了描述这种复杂的噪声，业界广泛使用 **泊松-高斯噪声模型（Poisson-Gaussian Noise Model）**，并用一个线性公式来近似噪声的**方差**（也就是噪声的强度/大小）：
$$Noise Variance = k × Signal + b$$
- **$k$（斜率）**：描述“信号依赖噪声”的强度（光越亮，噪声越大）。它主要由 Sensor 的增益（ISO）决定。
- **$b$（截距）**：描述“信号无关噪声”的强度（无论亮暗，电路都在产生噪声）。它代表 Sensor 的本底热噪声。

>  1**. 为什么光线越亮，光子随机波动越大，噪声就越大？**
> 这个问题触及了量子力学的底层逻辑。原因在于**光的粒子性**和**泊松分布（Poisson Distribution）**的数学特性。
> 
> - **光的本质是光子流**：Sensor 在固定时间内收集到的光子数量，并不是一个恒定不变的“常数”，而是一个遵循 **泊松分布** 的“随机数”。
>     
> - **泊松分布的“标准差”等于“均值的平方根”**：
>     
>     - 假设平均有 100 个光子打到 Sensor 上，那么它的随机波动（标准差）就是 √100 = 10。绝对波动是 10。
>         
>     - 假设平均有 10000 个光子（光线很亮），那么它的随机波动（标准差）就是 √10000 = 100。绝对波动是 100。
>         
> - **结论**：虽然亮光下的 100 比暗光下的 10 大得多，所以**从绝对数值上看，“亮区的噪声绝对值”确实比“暗区”大**。
>  
>  **核心补充（防止误解）**：  
> 虽然亮区的**绝对噪声**变大了，但它的**信噪比（信号/噪声）**却是变好的！亮区的信噪比是 10000/100 = 100，暗区是 100/10 = 10。所以人眼看亮区觉得很干净，只是因为信号强把噪声盖住了；而**去噪模型要处理的是那个“绝对噪声值”**，所以模型需要 `kmap`（亮度越大，k值越大）来告诉它：亮区虽然看着干净，但残留的绝对噪声依然需要处理。

#### 1.1.3.2 为什么是 `kmap` 和 `bmap`（地图），而不是 `k` 和 `b`（单个数字）？
因为真实照片存在 **“镜头阴影（Lens Shading）”** 和 **“暗角”** 现象！
- 照片**中心**的光线最足，边缘较暗。
- 照片**四角**的光线非常微弱。

既然噪声与亮度相关（`k * Signal`），那么照片**中心和边缘的噪声强度必然是不同的**！

如果给整张图只配一个 k 和一个 b，模型就只能“一刀切”地去噪。**这对中心（过降噪）和边缘（欠降噪）都不公平。**

所以，代码里生成了与图像**尺寸完全相同**的 k 图和 b 图：
- 对于明亮区域的像素，`kmap` 给一个**较大的值**（表示噪声大）。
- 对于暗部区域（如角落），`kmap` 给一个**较小的值**（表示噪声小），而 `bmap` 负责兜底读出噪声。
> **直观比喻**：  
> `kmap` 和 `bmap` 像是一张 **“噪声地形图”**。亮的地方是“高山”（噪声大，需要重拳出击），暗的地方是“平原”（噪声平缓，需要轻拿轻放）。模型拿到这张地图，就知道该在哪里用力去噪，在哪里保留细节。

#### 1.1.3.2 在代码中长什么样？（可视化）

在上面 `multi_dataset_loader` 返回的 `sample` 字典中：
```python
sample = {
    'input':  [B, 4, H, W],   # 带噪声的Bayer RAW图
    'target': [B, 4, H, W],   # 干净的RAW图
    'kmap':   [B, 1, H, W],   # K参数图（单通道，每个像素对应一个K值）
    'bmap':   [B, 1, H, W],   
    'noise_ctr': ...          # 其他控制参数
}
```

**关键点**：`kmap` 和 `bmap` 的**空间尺寸（H, W）**与输入图像**完全一致**。模型在推理时，会把它们拼接到输入特征中（例如将 4通道RAW + 1通道K + 1通道B = 6通道输入），让网络在逐像素处理时，随时可以参考当前像素点的噪声强度。
#### 1.1.3.3 ### 深度学习中的 `[B, 4, H, W]` 是什么意思？

这是 PyTorch/TensorFlow 中标准的**张量（Tensor）维度表示法**，遵循 **NCHW** 格式。

| 缩写    | 全称                  | 含义                 | 具体数值例子                                                     |
| ----- | ------------------- | ------------------ | ---------------------------------------------------------- |
| **B** | **Batch Size**（批大小） | 一次输入到模型中的**图片张数**。 | 如果 `B=8`，代表模型一次同时处理 8 张不同的 RAW 图。                          |
| **C** | **Channel**（通道数）    | 图片的**深度/图层数**。     | 普通 RGB 图是 3 通道。在这里，**`C=4`** 非常特殊，它代表 **Bayer 阵列的 4 个通道**！ |
| **H** | **Height**（高度）      | 图片垂直方向的像素个数。       | 比如 `H=1080`（高 1080 像素）。                                    |
| **W** | **Width**（宽度）       | 图片水平方向的像素个数。       | 比如 `W=1920`（宽 1920 像素）。                                    |

**重点解释：为什么 RAW 图是 `C=4`（4通道）而不是 1 通道？**
- 相机 Sensor 的 **Bayer 阵列**（如 RGGB）原本只有 1 层物理像素，但排成了马赛克状。
- 在数据预处理时，代码（通常用 `_kron_canvas` 函数）会把原始马赛克数据“拆开”并“叠起来”。
- **RGGB 拆解**：把原始图中所有 R 像素抽出来排成一幅小图，所有 G 像素抽出来排成另一幅，B 同理。
- 因为 RGGB 里有 1 个 R、2 个 G（通常分成 G1 和 G2）、1 个 B，所以叠起来就是 **4 个通道**。
- 这样模型就能在保持空间结构的前提下，高效地处理 Bayer 数据了。

#### 1.1.3.4 ISO是什么？
**ISO**（International Organization for Standardization，国际标准化组织），在相机中指的是 **感光度**。
- **物理本质**：它代表**模拟信号增益（Amplification）**。
- **工作原理**：Sensor 接收到光子产生电信号（电压）。ISO 就是把这个微弱的电压信号**放大**的倍数（ISO 100 是基础，ISO 3200 就是把这信号放大 32 倍）。
- **为什么 ISO 高，噪声就大？**：
    1. 放大信号的同时，**也把 Sensor 自身电路产生的“读出噪声”等比例放大了**。
    2. 结合刚才的泊松分布：高 ISO 通常用在暗光环境（光子少），信号本身就弱，再强行放大，底噪就变得极为明显。
**在代码中的体现**：  
在项目中，`k`（斜率）和 `b`（截距）是 **ISO 的函数**。“拟合 kb & ISO 曲线”，就是在做这件事：

```python 
# 伪代码逻辑
if ISO == 100:
    k = 0.0002, b = 0.0001
elif ISO == 1600:
    k = 0.0035, b = 0.0008  # k 和 b 都变大了！
```

模型拿到 `kmap` 和 `bmap`，实际上就**间接知道了当前这张图是用多少 ISO 拍的**，从而能自动调整去噪的“力度”。

#### 1.1.3.5 逻辑链
```
物理世界（光子） →  Sensor（光电转换） →  ISO（放大信号） →  数据格式（B,4,H,W） →  模型输入
       │                    │                    │                     │
   泊松分布              Bayer阵列            kb参数缩放            RGGB拆解
（亮区噪声大）        （马赛克排列）     （kmap/bmap取值依据）   （4通道张量）
```
#### 1.1.3.6 模型为什么需要它们？（条件输入）
如果没有 `kmap` 和 `bmap`，模型只能从像素的数值中“猜测”噪声有多大。但真实值可能非常模糊（例如：夜景的高ISO 和 白天的低ISO，同一个像素值可能对应完全不同的噪声）。

**显示地传入 k 和 b 参数，相当于给模型开了“上帝视角”**：
- 模型不需要自己去猜亮度-噪声的关系。
- 模型可以直接根据 `kmap` 中的大数值，提高该区域的去噪强度。
- 模型可以根据 `bmap` 的值，了解电路本底噪声有多大。

这就是 **“噪声模型的应用：基于 Noise Normalization 和 Noisemap（即 kmap/bmap）”** 的核心意义。

#### 1.1.3.7 这些 `kmap` 和 `bmap` 是怎么算出来的？
这就是 **“数据库的建立及 Sensor 噪声的建模”** 和 **“噪声标定”** 干的事情：
1. 拍摄全黑图（盖住镜头）→ 测得 `b`（读出噪声）。
2. 拍摄不同亮度的灰阶图（从黑到白）→ 统计每个亮度下的噪声方差。
3. 拟合出一条直线（方差 vs 亮度），斜率就是 `k`，截距就是 `b`。
4. 由于镜头边缘暗，标定系统会生成一张 **二维网格表**，记录每个像素位置的 `k` 和 `b`。

## 1.2 第2+3步：前向传播 + 损失计算

```python
loss, loss_dict = self.loss_fn.cal_iir_model_loss(sample)
```
这行代码是 **整个循环里最重要、也最难懂的一行**，因为它内部同时做了“前向传播”和“计算损失”。我们拆开看：
### 1.2.1 这行代码的表面意思

|代码片段|解释|
|---|---|
|`self.loss_fn`|这是一个“损失计算器”对象，专门负责算Loss|
|`.cal_iir_model_loss`|这个对象里的一个方法（函数），名字叫“计算IIR模型损失”|
|`(sample)`|把刚才加载的数据“包裹”传给这个函数|
|`loss, loss_dict =`|函数返回两个东西：  <br>- `loss`：总损失（一个数字，比如 0.235）  <br>- `loss_dict`：详细损失（比如L1是多少、SSIM是多少，用来记录日志）|

### 1.2.2 这个函数内部（`cal_iir_model_loss`）做了什么？

**内部步骤 A：前向传播（对应笔记 ② 模型）**

```python

# 在 iir_train_ops.py 第93行
net_out0, _ = self.model_fn(ref_img, input_img_decomp, snr_self_ref, param, param)

- `self.model_fn`：就是神经网络模型
    
- `input_img_decomp`：就是上面传进来的 `sample['input']`（带噪声的图）
    
- `net_out0`：模型输出的结果，也就是 ŷ（预测的去噪图）
```
    
这行就是笔记里的 **前向传播**：ŷ = f_θ(x)


**内部步骤 B：计算损失（对应笔记 ③ 损失）**

```python

# 在 iir_train_ops.py 第161行开始
# 计算 L1 Loss（像素差）
raw_loss_l1 = self.l1_loss(net_out, target_mix_noise)  # target就是 sample['target']
raw_loss_l1 = 0.16 * raw_loss_l1   # 乘以权重0.16
loss_sum += raw_loss_l1            # 累加到总损失里
# 计算 SSIM Loss（结构差）
raw_loss_ssim = 1 - pt_reduce_mean_ssim(target_mix_noise, net_out)
raw_loss_ssim = 0.84 * raw_loss_ssim  # 乘以权重0.84
loss_sum += raw_loss_ssim             # 再累加
# ... 还有其他好几种损失（UV通道、时间一致性、运动区域等）都累加进来
# 最后返回 loss_sum（一个数字，比如0.235）
return loss_sum, loss_dict
```

> 对应笔记里的 **③ 损失**：`Loss = L(ŷ, y_true)`，这里算的就是这个。

---

### 第4步：清除旧梯度

```python
self.optimizer.zero_grad()
```

|代码|解释|
|---|---|
|`self.optimizer`|优化器（Adam），负责更新参数|
|`.zero_grad()`|把所有参数的“梯度”清零|

**为什么需要这行？**  
PyTorch 默认会**累加**梯度（为了支持大Batch训练）。如果不清零，这次算的梯度会和上次的加在一起，参数更新方向就乱掉了。所以每次迭代前必须先清零。


### 第5步：反向传播（计算梯度）

```python
loss.backward()
```

| 代码            | 解释                     |
| ------------- | ---------------------- |
| `loss`        | 刚才算出来的总损失（一个数字，如0.235） |
| `.backward()` | PyTorch 的自动求导函数        |

**这行触发了什么？**
1. 从 `loss` 这个数字开始，沿着计算图**倒着走**
2. 用**链式法则**计算出 Loss 对每个参数的偏导数 ∂L/∂w_i
3. 把结果存到每个参数的 `.grad` 属性里
> 对应笔记里的 **④ 反向传播**。

---

### 第6步：优化器更新参数

```python
self.optimizer.step()
```

|代码|解释|
|---|---|
|`self.optimizer`|优化器（Adam）|
|`.step()`|执行一步参数更新|

**这行做了什么？**

```
对于模型里的每一个参数 w：
    w_new = w_old - 学习率 × (w_old 的梯度)
```
对应笔记里的 **⑤ 优化器**：θ_new = θ - η · ∇_θ L

## 三、完整的一步流程（把上面串起来）

```
一次迭代（处理1个Batch）的完整路线：
1. sample = multi_dataset_loader()
   └── 从硬盘读取一批 (噪声图, 干净图)
2. loss = cal_iir_model_loss(sample)
   ├── 内部①：net_out = model(sample['input'])    ← 前向传播
   └── 内部②：loss = L1(net_out, target) + SSIM(...) ← 算Loss
3. optimizer.zero_grad()      ← 清空旧梯度
4. loss.backward()            ← 反向传播，算梯度
5. optimizer.step()           ← 用梯度更新参数
然后回到第1步，用下一批数据继续。
```
