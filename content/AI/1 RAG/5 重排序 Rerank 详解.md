## 1. 核心概念：什么是 Rerank

Rerank（重排序）是 RAG 系统中的第二阶段排序技术。初始检索（向量检索 / BM25）从大规模知识库中快速召回大量候选文档（如 Top-100），Rerank 对这些候选进行精细的二次评分和排序，只将最相关的少量文档（如 Top-5）传递给 LLM 用于生成答案。检索和 Rerank 的核心定位区别如下：

| 维度   | 检索（Retriever）        | 重排序（Rerank）         |
| ---- | -------------------- | ------------------- |
| 目标   | "宁可错杀一千，绝不放过一个"（高召回） | "精挑细选，去粗取精"（高精度）    |
| 输入   | 全量知识库                | 检索返回的候选集（如 Top-100） |
| 输出   | 候选文档列表（粗排）           | 候选文档列表（精排）          |
| 速度   | 快（毫秒级）               | 相对慢（逐对计算）           |
| 可扩展性 | 可处理百万级文档             | 仅处理百/千级文档             |

**为什么检索的排序不够用？** 向量检索（Bi-Encoder）将 Query 和 Document 独立编码后计算向量相似度，这种"粗略相似度"缺乏精细的语义交互。常见现象是：检索结果中真正回答问题的文档排在第 3 位，前 2 篇只是泛泛的背景介绍。LLM 拿到这样的上下文，关键信息埋在后面，生成质量必然下降。

> 技术要点：可以把 Rerank 理解为两个阶段——"初筛（海选）+精排（决赛）"。检索是"快手阿姨"，30 秒抓 10 个苹果（看外表）；Rerank 是"品果大师"，接过 10 个苹果仔细检查（摸一摸、闻一闻、掂一掂），告诉你哪 3 个最好吃。

## 2. 技术原理：Bi-Encoder vs Cross-Encoder

理解 Rerank，必须理解两种编码架构的根本区别。

### 2.1 Bi‑Encoder（检索用）

- 原理：Query 和 Document 分别独立编码为向量，相似度通过余弦值计算
- 优点：Document 向量可离线预计算，查询时只需计算一次 Query 向量，速度极快，适合大规模召回
- 缺点：Query 和 Document 从不"见面"，编码时各自不知道对方存在，相关性判断较粗
- 使用场景：第一阶段检索，对全量知识库快速召回候选文档

### 2.2 Cross‑Encoder（Rerank 用）

- 原理：Query 和 Document 拼接在一起，同时输入模型，Transformer 的 Self‑Attention 让 Query 的每个词和 Document 的每个词充分交互，直接输出一个相关性分数
- 优点：精细语义匹配，能捕捉深层的逻辑关系
- 缺点：每对 (Query, Document) 都要独立计算，无法预计算，速度慢
- 使用场景：第二阶段精排，对少量候选文档精细评分

| 对比维度 | Bi-Encoder | Cross-Encoder |
|----------|------------|----------------|
| 编码方式 | Query 与 Document 独立编码 | Query 与 Document 拼接后联合编码 |
| 信息交互 | 仅最后一步点积交互 | 全程 Attention 交互 |
| 速度 | 极快（Doc 向量可预计算） | 慢（需逐对计算） |
| 精度 | 一般（粗排） | 高（精排） |
| 使用阶段 | 第一阶段检索 | 第二阶段 Rerank |

> 技术要点：正确用法是**串联**而非替代——Bi‑Encoder 先快速召回候选集，Cross‑Encoder 再精细排序。一个通俗的例子："Bi‑Encoder 是海选，速度第一；Cross‑Encoder 是决赛，精度第一。"

## 4. Rerank 的评估指标

| 指标 | 定义 | 说明 |
|------|------|------|
| **nDCG@K**（归一化折损累积增益） | 按位置衰减衡量排序质量 | 更关注"好结果是否排在前面"，支持多级相关性 |
| **MRR**（平均倒数排名） | 第一个正确答案的排名倒数平均值 | 关注"第一个正确答案有多靠前" |
| **context_precision** | 相关文档排在不相关文档之前的比例 | RAGAS 专门衡量排序质量的指标，是 Rerank 要优化的核心 |
| **Hit Rate@K** | 前 K 个结果中是否包含正确答案 | 衡量召回覆盖能力，Rerank 通常能稳定提升 |
| **Recall@K** | 正确答案在返回结果中的比例 | Rerank 的主要目标是提升排序质量，K 较小时 Recall 通常下降 |

> 技术要点：RAGAS 的 context_precision = 1.0 表示相关文档全部排在不相关文档前面，这正是 Rerank 的核心优化目标。

## 5. Rerank 在 RAG 中的集成架构

```
用户 Query
    ↓
[检索阶段] Bi‑Encoder (向量 / BM25)
    ↓ 快速召回 100‑1000 个候选文档
[Rerank 阶段] Cross‑Encoder 逐对评分
    ↓ 精排后保留 Top‑5
[生成阶段] LLM 基于高质量上下文生成答案
```

### 成本-精度权衡

- 在 RAG 架构中，Rerank 并非无条件使用。需根据语料库特定的评估提升和延迟预算来决策。
- 常见生产配置：检索 Top‑50 到 Top‑100，Rerank 后输出 Top‑5 到 Top‑10。
- 好的 Rerank 模型能在不显著增加延迟的前提下，将 MRR、nDCG 等核心指标提升 20%–50%。
- 阈值可作为经验参考：若检索结果中前 3 条已经高度相关，Rerank 收益有限；反之若前 3 条中混入大量噪声，Rerank 收益显著，应优先优化 Rerank。

> 技术要点：Rerank 同时带来**降本增效**——减少无关文档的 Token 消耗，降低 LLM 推理成本，同时提升生成质量。

## 6. 常见误区与澄清

- 误区一："Rerank 可以替代检索。"——Rerank 无法处理百万级文档，必须先由检索快速缩小候选范围。
- 误区二："Rerank 一定会提升效果。"——若检索召回质量极差（相关文档根本不在 Top‑100 内），Rerank 无法起死回生。
- 误区三："只用最贵的模型。"——需根据场景（中文/英文、预算、延迟）选型。
- 误区四："Rerank 和微调是替代关系。"——两者是互补的：Rerank 优化排序，微调优化生成，可同时使用。

## 7. 技术问答

### Q1：Rerank 在 RAG 中起什么作用？
**回答**：Rerank 解决检索阶段"召回多但排序粗"的问题，用 Cross‑Encoder 对候选文档精细重排，把最相关的文档排在前面，提升 LLM 生成的准确性和上下文质量，同时能降低 Token 消耗。

### Q2：Bi‑Encoder 和 Cross‑Encoder 的核心区别？
**回答**：Bi‑Encoder 分别编码 Query 和 Document，最后算向量相似度，速度极快但交互不足，用于第一段检索。Cross‑Encoder 把两者拼接后联合编码，每一层 Attention 都让词与词交互，精度高但速度慢，用于第二阶段精排。

### Q3：如何为项目选择 Rerank 模型？
**回答**：从四个维度权衡：①精度；②延迟；③成本（API 按量 vs 自托管）；④语言与数据隐私。中文技术文档场景推荐 bge-reranker-v2-m3，追求精度且不想自托管选 Rerank 4 API（或对应托管服务）。

### Q4：Rerank 会增加多少延迟？怎么解决？
**回答**：Cross‑Encoder 逐对计算确实增加延迟。但工程上可通过**限制传入 Rerank 的候选文档数量**（如 Top‑50 而非 Top‑100）、使用 GPU 推理、批处理等方式缓解。Rerank 的延迟通常与参数量正相关：轻量模型（如 BGE‑v2‑m3）约 80ms，4B 大模型可达数百毫秒。

### Q5：Rerank 和微调的区别是什么？
**回答**：Rerank 不改变生成模型，只优化检索排序；微调直接修改生成模型参数，让模型学习特定领域的回答风格或知识。两者是正交的优化手段，可同时使用。

### Q6：Rerank 如何评估效果？
**回答**：核心指标是 nDCG@K、MRR 和 RAGAS 的 context_precision。在同一测试集上对比"不加 Rerank"和"加 Rerank"前后的指标变化。

## 8. 学习路线建议

1. **理解原理**：精读 Bi‑Encoder 与 Cross‑Encoder 的区别（1 小时）
2. **模型调研**：对比主流 Rerank 模型的选型，明确自己场景的优先选项（1 小时）
3. **轻量实验**：选择轻量级模型（如 bge-reranker-v2-m3）本地跑通 Rerank 流程（2 小时）
4. **集成评估**：集成到现有 RAG 项目，用同一测试集对比有无 Rerank 的指标提升（2 小时）
5. **成本调优**：调整传入 Rerank 的候选数（如 50→30），测量精度与延迟的平衡点（1 小时）
