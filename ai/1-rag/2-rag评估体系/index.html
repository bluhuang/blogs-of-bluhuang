RAG评估体系

1 RAG 评估体系层级

RAG 评估可分为三个层级，每个层级回答不同的问题：

层级核心问题这一层的重点
检索层检索器能不能找到相关信息？评估检索的准确性（是否召回相关片段）和效率（响应速度）
生成层生成器基于检索结果能不能答好？评估生成的忠实度（不编造）、相关性（不跑题）、完整性（不遗漏）
端到端整个系统用户觉得好用吗？评估用户体验（满意度）、业务价值（任务完成率）

1.1 检索层评估 —— 衡量“能不能精准找到相关信息”

检索是 RAG 的基础。若检索到的文档片段（Chunk）与用户问题无关，生成环节再优也会导致“答非所问”。

指标（全称/缩写）定义计算公式为何能达成评估目的？
Precision@K（精确率@K）返回的前 K 个结果中，相关文档的比例结果中相关文档数量 / K衡量结果中的“纯净度” —— 用户不想在一堆无关结果里找答案
Recall@K（召回率@K）所有相关文档中，被返回前 K 个里的比例在K个结果里的相关文档数 / 总相关数衡量是否“漏掉”了重要信息 —— 漏掉关键文档会导致答案残缺
F1@K（F1分数@K）Precision 和 Recall 的调和平均2 * P * R / (P+R)同时惩罚“低精确率”（太多无关结果）和“低召回率”（漏掉关键文档），单一数字综合评价
MRR（Mean Reciprocal Rank，平均倒数排名）第一个相关文档的排名倒数的平均值对每个查询，取第一个相关文档排名的倒数，再对所有查询求平均。例如：第一个相关文档排第1位则得1分，排第3位则得1/3≈0.333。关注“第一个正确答案出现的位置” —— 用户希望第一个结果就是有用的，排名靠后则体验差
Hit Rate@K（命中率@K）前 K 个结果中是否至少有一个相关文档二值指标：有相关文档 = 1，否则 = 0最简单的“有没有”指标，适合快速对比检索策略的优劣
NDCG@K（Normalized Discounted Cumulative Gain，归一化折损累积增益）考虑排名的累积增益，且允许“部分相关”（如相关度分为 0/1/2）计算 DCG = Σ(2^rel_i - 1)/log2(i+1)，再除以 IDCG（理想排序下的最大 DCG）能区分“部分相关”与“完全相关”，且对排名位置敏感：相关结果越靠前，分数越高。适合精细排序优化
Latency（延迟）检索耗时（毫秒）从发起查询到返回结果的时间工程指标：用户能接受的等待时间有限，过长会放弃使用
Coverage（覆盖率）有检索结果的查询比例有返回结果的查询数 / 总查询数极端情况：某些查询可能召回为空，覆盖率低意味着系统无法回答很多问题

补充说明

1. 什么是调和平均？

对于两个正数 $a$ 和 $b$，调和平均定义为： $$ H = \frac{2}{\frac{1}{a} + \frac{1}{b}} = \frac{2ab}{a + b} $$ 更一般地，对于 $n$ 个数，调和平均是 $\frac{n}{\sum \frac{1}{x_i}}$。

特点：调和平均总是小于或等于算术平均和几何平均，当数值差异很大时，调和平均更接近小值。即它对极端小值非常敏感。

2. 为什么 F1 分数用调和平均而不是算术平均？

F1 分数是 Precision（精确率）和 Recall（召回率）的调和平均： $$ F1 = 2 \cdot \frac{P \cdot R}{P + R} $$ 原因：调和平均更能反映“两者都要高”的要求。

  • 算术平均：如果 $P = 1.0$（完美），但 $R = 0.1$（极差），算术平均 = (1.0+0.1)/2 = 0.55，看上去还行，但这掩盖了 Recall 很差的现实。
  • 调和平均：$H = \frac{2 \times 1.0 \times 0.1}{1.0 + 0.1} = \frac{0.2}{1.1} \approx 0.18$，分数很低，正确反映了有一个指标很差。

直观例子：一个检索系统返回了 1 个结果且它是正确的（Precision=100%），但本该找到的 100 个相关文档只找到了 1 个（Recall=1%）。算术平均 50.5% 看起来还行，但实际上系统几乎不能用。调和平均 1.98% 立刻警示“召回太差”。

调和平均的惩罚特性

  • 当两个数相差悬殊时，调和平均更靠近较小的那个数。
  • 只有当 两个数都接近 1 时，调和平均才接近 1。
  • 这符合 F1 的设计初衷：只有精确率和召回率同时高，F1 才高。
NDCG 简要总结
  • 全称：Normalized Discounted Cumulative Gain（归一化折损累积增益）
  • 作用：评估排序质量，兼顾多级相关性和排名位置（越靠前权重越高）

核心公式

  1. DCG（折损累积增益）：( DCG@K = \sum_{i=1}^{K} \frac{rel_i}{\log_2(i+1)} )
    或常用增强版：( DCG@K = \sum_{i=1}^{K} \frac{2^{rel_i}-1}{\log_2(i+1)} )
    • ( rel_i )：第 i 个结果的相关性等级（如 0=无关，1=部分相关，2=高度相关）
  2. IDCG：理想情况（按相关性降序排列）下的 DCG
  3. NDCG：( NDCG@K = \frac{DCG@K}{IDCG@K} )（值域 [0,1]，越大越好）

特点与使用场景

特点说明
支持多级相关性可以区分“高度相关”和“部分相关”，比二元指标更细腻
位置敏感相关结果越靠前，得分越高，更贴近用户期望
归一化不同查询的 NDCG 可以直接比较（因为除以 IDCG）
对 K 值敏感NDCG@K 关注前 K 个结果，适合评估“用户只看前几页”的场景

在 RAG 检索评估中的应用：

  • 当检索器返回多个文档片段，有些片段直接包含答案（高度相关），有些是背景知识（部分相关），NDCG 可以精细评估排序质量。
  • 优化重排序（Rerank）时，NDCG 是最适合的指标。

与 MRR/Hit Rate 对比

指标多级相关性位置敏感考虑多个相关结果
Hit Rate❌❌❌
MRR❌✅（仅第一个）❌
NDCG✅✅✅

一句话：NDCG 是衡量排序“好结果是否排在前面”的最精细指标。

1.2 生成层评估 —— 衡量“基于检索信息，能不能生成优质回答”

生成层的核心是：忠实度（不胡说）、相关性（不跑题）、完整性（不漏信息）。分为定量指标（自动）和定性指标（人工）。

定量指标（自动评估）

指标（全称/缩写）含义计算方式为何能达成评估目的？
Faithfulness（忠实度 / 接地性）生成答案是否完全基于检索到的上下文，没有编造事实1. 将答案分解为若干“声明”（如通过 LLM 拆成短句）；2. 对每个声明，用 LLM 判断是否可以从上下文中推断；3. 计算被支持的声明比例。RAG 的核心目标是“开卷考试”，答案必须来自资料。Faithfulness 直接衡量“有无幻觉”。
Answer Relevancy（答案相关性）答案是否直接回答了用户问题，没有答非所问或废话1. 用 LLM 从答案中反向生成可能的问题；2. 计算生成的问题与原始问题的语义相似度（如使用嵌入向量余弦距离）。低分意味着答案虽然可能正确，但偏离了用户想问的。例如用户问“如何排查 CPU 高？”，答案却讲“CPU 的定义”。
Context Relevancy（上下文相关性）检索到的上下文是否与问题相关1. 用 LLM 评估上下文中的每个句子对回答问题是否有用；2. 计算有用句子的比例（或加权分数）。低分说明检索阶段召回了大量无关内容，会干扰生成，应优先优化检索器。
BLEU（Bilingual Evaluation Understudy，双语评估替补）候选答案与参考答案的 n-gram 重叠度计算候选答案中出现在参考答案里的 n-gram 数量比例，并对长度做惩罚。传统机器翻译指标。适合有标准答案的封闭式任务（如摘要），但对开放式问答不太敏感（因为正确答案表达方式多样）。
ROUGE（Recall-Oriented Understudy for Gisting Evaluation，面向召回的摘要评估替补）重点关注参考答案中的内容是否被候选答案覆盖常用 ROUGE-L：计算最长公共子序列（LCS）的 F 值。适合评估摘要任务，检查关键信息是否被包含。
BERTScore基于 BERT 的语义相似度1. 将候选答案和参考答案分别转为 BERT 的词向量序列；2. 计算词级别的最佳匹配相似度，再汇总为 Precision/Recall/F1。相比 BLEU/ROUGE 的词重叠，BERTScore 能捕捉语义相似（如“快速”和“迅速”），更接近人类判断。

关于温度（temperature）：temperature 是 LLM 生成时的超参数，控制输出随机性。取值范围 02，值越低模型越确定（倾向于选概率最高的词），值越高输出越多样。RAG 中为了减少幻觉，常将 temperature 设为较低值（如 0.10.3），让模型更忠实于上下文。

n-gram 是什么？

n-gram 是自然语言处理中常用的概念，指文本中连续的 n 个词（或字符）组成的序列。

  • unigram (1-gram)：单个词。例如 “我/爱/北京” → “我”、“爱”、“北京”。
  • bigram (2-gram)：连续两个词。例如 “我爱”、“爱北京”。
  • trigram (3-gram)：连续三个词。例如 “我爱北京”。

n-gram 的核心思想是：两个文本越相似，它们共享的 n-gram 就越多。n 越大，对词序和短语结构的匹配越严格（例如 “猫追狗” 和 “狗追猫” 的 unigram 完全相同，但 bigram 完全不同）。

BLEU（Bilingual Evaluation Understudy）

BLEU 是一种评估机器翻译（或其他生成文本）与一个或多个参考译文相似度的指标。核心思想：统计候选翻译中出现在参考译文中的 n-gram 数量，并对过短的翻译进行长度惩罚。

计算步骤：

  1. 计算 n-gram 精确率（通常取 n=1~4）： $$P_n = \frac{\sum_{n\text{-gram} \in \text{Candidate}} \text{Count}{\text{clip}}(n\text{-gram})}{\sum{n\text{-gram} \in \text{Candidate}} \text{Count}(n\text{-gram})}$$
    • $\text{Count}_{\text{clip}}(n\text{-gram})$ 表示将该 n-gram 在候选句子中的出现次数裁剪到不超过它在任何参考句子中的最大出现次数（避免重复词被过度奖励）。
  2. 计算长度惩罚 BP（Brevity Penalty）：
    • 设 $c$ 为候选句子长度，$r$ 为参考句子长度（若多个参考，取与 $c$ 最接近的长度）。
      若 $c > r$，则 $BP = 1$；否则 $BP = e^{(1 - r/c)}$。
    • 惩罚过短的候选翻译（即使 n-gram 匹配率高，但漏译内容也要扣分）。
  3. 最终 BLEU： $$ \text{BLEU} = BP \cdot \exp\left(\sum_{n=1}^{N} w_n \log P_n\right)$$ 通常 $N=4$，$w_n = 1/4$（等权平均）。

特点：

  • 优点：计算快，与人工评价有一定相关性，广泛用于机器翻译。
  • 缺点：对词序不敏感（例如 “猫追狗” 和 “狗追猫” 可能得分相近），且需要参考译文，不适合开放式生成任务。
ROUGE（Recall-Oriented Understudy for Gisting Evaluation）

ROUGE 是面向摘要任务的评估指标，侧重于参考摘要中的内容是否被候选摘要覆盖（即召回率）。常用变体是 ROUGE-L（基于最长公共子序列）。

ROUGE-L 计算候选摘要与参考摘要的最长公共子序列（LCS，Longest Common Subsequence） 的 F 值。

  • 公共子序列：不要求连续，但保持相对顺序。例如 “我爱北京” 和 “北京我爱” 的 LCS 是 “北京” 或 “我”，长度仅为 1（若词序不一致则 LCS 很短）。
  • LCS 长度 $L$。

计算：

  • 召回率 $R_{\text{lcs}} = \frac{L}{\text{len(参考)}}$
  • 精确率 $P_{\text{lcs}} = \frac{L}{\text{len(候选)}}$
  • $$ \text{ROUGE-L} = \frac{(1+\beta^2) R_{\text{lcs}} P_{\text{lcs}}}{R_{\text{lcs}} + \beta^2 P_{\text{lcs}}} $$ $\beta$ 通常取很大（如 $\beta \to \infty$）使 F 值约等于召回率，即强调覆盖程度。

特点：

  • 优点：自动衡量内容覆盖度，不要求词序完全一致，适合摘要评估。
  • 缺点：仍依赖参考摘要，无法评估事实正确性（例如生成了一句语法通顺但错误的内容，若参考中不存在，ROUGE 会忽略它）。
BERTScore

BERTScore 利用 BERT 的上下文词向量计算候选与参考的语义相似度，能捕捉同义词替换、语序变化等深层语义匹配。

计算步骤：

  1. 用 BERT 分别将候选句子 $x$ 和参考句子 $y$ 编码为上下文词向量序列： $$\mathbf{x} = {\mathbf{x}_1, …, \mathbf{x}_m}, \quad \mathbf{y} = {\mathbf{y}_1, …, \mathbf{y}_n}$$
  2. 对候选中的每个词 $x_i$，计算它与参考中所有词 $y_j$ 的余弦相似度，取最大值作为该词的匹配分数： $$\text{sim}(x_i, y) = \max_{j} \ \frac{\mathbf{x}_i^\top \mathbf{y}_j}{|\mathbf{x}_i| |\mathbf{y}_j|}$$
  3. 召回率（参考中内容被候选覆盖的程度）： $$ R_{\text{BERT}} = \frac{1}{n} \sum_{j=1}^{n} \max_{i} \text{sim}(x_i, y_j) $$ 精确率（候选中的内容与参考相关的比例）： $$ P_{\text{BERT}} = \frac{1}{m} \sum_{i=1}^{m} \max_{j} \text{sim}(x_i, y_j) $$
  4. F1 值： $$ \text{BERTScore} = 2 \cdot \frac{P_{\text{BERT}} \cdot R_{\text{BERT}}}{P_{\text{BERT}} + R_{\text{BERT}}} $$
