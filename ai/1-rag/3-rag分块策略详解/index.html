    RAG 系统中的文本分块（Chunking）学习笔记#

    1. 引言：为什么分块是 RAG 的基石？#

    RAG 系统在文档进入检索环节之前，必须经过文本分块处理——把大文档切分成更小的、有意义的片段。每个分块应当是连贯且自包含的，这样检索器才能快速定位并返回最相关的信息。

    分块之所以重要，体现在三个层面：

    • 突破嵌入模型的输入长度限制：多数 Embedding 模型对输入长度有严格限制（如 512 token），分块是必要的工程前提。
    • 提升检索的信噪比：块过大时无关内容稀释信号；块过小时语境不足，容易“只命中词不命中义”。
    • 维护语义连续性：跨段落、跨章节的语义关系常在边界处被切断，劣质分块会导致上下文断裂、幻觉频发。

    行业共识：分块决定了 RAG 检索质量的 70%，嵌入模型和检索器只能弥补剩下的 30%。

    2. 核心概念速览#

    概念定义核心作用
    Chunk经过分块处理后，用于检索和生成的文本片段检索的最小单元，直接影响检索粒度和语义完整性
    Chunk Size每个 Chunk 的大小，通常以 Token 数衡量决定检索的细粒度——size 越小定位越精确，但可能丢失上下文
    Chunk Overlap相邻两个 Chunk 之间共享的 Token 数量缓解信息在边界处被割裂的问题，保证上下文的连续性

    3. Chunk Size、Overlap、语义边界对检索的影响#

    3.1 Chunk Size 的影响#

    Size 范围优点缺点适用场景
    小（128-256 token）检索精确度高，噪声少，易定位具体事实上下文不足，可能丢失支撑推理的周边信息事实性问答、错误码查询
    中（256-512 token）平衡精确度和上下文，多数场景表现稳定无明显短板通用 RAG 基线
    大（512-1024+ token）保留完整段落/章节，适合复杂推理信噪比下降，检索易被无关内容干扰长文档分析、多跳推理

    核心规律：事实类查询适合小块，复杂分析适合大块。没有绝对最优的 size，必须用评估数据驱动决策。

    3.2 Chunk Overlap 的影响#

    Overlap（重叠）通过在相邻块之间共享一部分内容，缓解“边界切断语义”的问题。

    • 无重叠：成本最低，但关键信息可能刚好落在两个块的边界，导致两面都检索不到。
    • 10%-20% 重叠：经验最优区间，能有效召回边界信息，同时开销可控。
    • 过高重叠（>30%）：导致索引膨胀、嵌入成本翻倍、近似重复泛滥、重排序器负载飙升。收益递减，成本线性增长。

    核心规律：重叠是“保险”，不是越大越好。10%-20% 是多数场景的安全区间。

    3.3 语义边界的影响#

    语义边界指文档中自然意义上的段落、章节、主题转换点。

    • 忽略语义边界（仅按固定长度切分）：容易切断句子、分离因果链。例如，在一段关于“慢查询原因分析”的文字中间切断，前半段只看到“连接池满”，后半段只看到“索引缺失”，两部分都无法独立回答问题。
    • 尊重语义边界（基于段落、标题切分）：每个 Chunk 自成完整的逻辑单元，检索时能直接提供可用的信息片段，减少 LLM 的推理负担。

    核心规律：语义边界比字符数更重要。优先选择基于文档结构的分块方式，实在没有结构时才退回到递归分块。

    4. 主流分块策略详解#

    策略原理优点缺点适用场景
    固定大小分块按预设 Token 数机械切分简单快速、行为可预测极易切断句子、割裂语义日志、代码、结构混乱的大规模语料库
    基于句子分块以完整句子为基本单元切分语法完整、语义连贯句子长度不均，块大小差异大新闻、文章等叙事性文本
    基于段落分块以完整段落作为切分单元保留篇章级上下文段落长短不一，可能导致块过大研究论文、长文档、综述
    递归分块按优先级（段落→句子→词）递归拆分兼顾文档结构与尺寸限制实现相对复杂通用文本的首选基线策略
    语义分块用 NLP 模型计算句子间相似度，在主题变化处切分分块与语义高度匹配计算成本高，阈值难调多主题对话、结构复杂的文档
    基于结构分块利用 Markdown 标题、HTML 标签切分分块自带元数据，可追溯性强严重依赖文档格式完整度技术文档、网页
    滑动窗口分块固定窗口按设定重叠滑动生成重叠块能追踪跨长文档的“演变”产生大量冗余，存储开销大医疗记录、日志文件
    LLM 分块让 LLM 判断文档的自然分割点召回率最高（可超 90%）计算开销极大，成本高高精度要求、文档量不大的场景
    元数据增强分块附加部门、时间戳等元数据到 Chunk检索精度可提升数倍（5x）需额外构建元数据体系企业级知识库、多源数据

    4.1 层次化分块（Hierarchical Chunking）#

    层次化分块是一种多层级架构，并非单一的切分方式，而是一个检索策略框架。

    核心思想：同时维护多个粒度的分块——小分块负责细粒度精确检索，中等分块支撑平衡推理，大分块维持全局上下文。

    工作流程：

    1. 离线阶段：对同一文档生成多级 Chunk。例如：

      • 小分块（句子级，256 token）
      • 中分块（段落级，512 token）
      • 大分块（章节级，1024+ token）
      • 并为各级 Chunk 建立关联（小分块所属的中分块和大分块 ID）

    2. 检索阶段：先用小分块快速定位精确匹配位置，再通过关联 ID 拉取对应的中大分块补充完整上下文。

    优势：

    • 兼顾精确与全面：小分块保证高精度，大分块提供背景信息，有效压制幻觉。
    • 提升多跳推理深度：复杂问题需要的证据常散落在多个小分块中，通过大分块能串联起因果链。

    典型应用：LlamaIndex 的 HierarchicalNodeParser 就是这种多粒度检索的具体实现。企业级 RAG 系统普遍采用层次化分块来平衡精度与上下文宽度。

    5. 总结速览#

    关键点核心结论
    分块的重要性RAG 检索质量的 70% 由分块决定，是地基中的地基
    基线配置512 token + 10% overlap + 递归分块，作为起点
    调参原则用评估指标驱动，事实问题用小块，复杂问题用大块
    语义边界优先基于标题/段落切分优于固定长度切分
    层次化分块多粒度检索，小块定位 + 大块补上下文，压制幻觉
