噪声的原理 —— 从物理源头到AI建模

BluHuang / Ai / 2026年7月1日

一、噪声是什么？—— 从“为什么有噪点”说起

1.1 直观感受：噪声就是“不该出现的像素值”

你肯定见过这样的照片：

  • 夜晚拍的室内照片，暗部区域有密密麻麻的彩色小点
  • 蓝天照片里，原本纯净的蓝色区域出现细小的颗粒感
  • 用高ISO（如ISO 3200）拍的图，整个画面像铺了一层“沙”

这些“不该出现的像素值偏差”，就是噪声。

1.2 噪声的物理来源：光本身的“粒子性”

要理解噪声，得从“光是什么”说起。

光是光子流：光的本质是一颗一颗的“光子”（光粒子）。相机Sensor的工作就是在固定时间内“数”有多少光子打到了每个像素上。 关键洞察：光子到达Sensor的过程是随机的。

这就引出了第一个噪声来源——光子散粒噪声（Shot Noise）：

  • 光线越亮 → 光子数量越多 → 绝对波动越大
  • 光线越暗 → 光子数量越少 → 绝对波动越小

但有一个关键点经常被误解：虽然亮区的绝对噪声值更大，但亮区的信噪比（信号/噪声） 其实更高。因为信号增长的速度（N）比噪声增长的速度（√N）快得多。所以人眼看亮区会觉得“干净”，看暗区会觉得“脏”。

1.3 噪声的第二个来源：电路本身

光子打到Sensor上被转换成电信号（电压）。但这个电压在传输和放大的过程中，会被电路本身的热运动干扰——就像你在听收音机时，喇叭里会有“沙沙”的底噪。

这就是读出噪声（Read Noise）：

  • 无论光线多亮或多暗，读出噪声都存在
  • 它基本不随信号强度变化，是一个固定大小的“底噪”

1.4 噪声的第三个来源：量化误差（Bit Depth）

Sensor把电压转换成数字（模数转换，ADC）时，会受限于位深（Bit Depth）：

  • 12位深 → 只能表达 0 ~ 4095 的灰度值
  • 光子的真实强度可能是 1234.7，但ADC只能记录为 1234 或 1235
  • 这个“四舍五入”的误差也是一种噪声

1.5 一句话总结噪声的构成

总噪声 = 光子散粒噪声（与亮度有关）+ 读出噪声（与亮度无关）+ 量化噪声（与位深有关）

二、噪声建模 —— 用数学描述噪声

2.1 为什么要“建模”？

我们需要一个数学模型来描述噪声的行为，原因有三个：

  1. 标定：在新Sensor上线前，用模型快速评估它的噪声特性
  2. 合成数据：用模型生成大量“带噪声+干净”的配对数据，供AI训练
  3. 算法设计：知道了噪声的数学形式，才能设计出针对性的去噪算法

2.2 核心模型：泊松-高斯噪声模型

在ISP工业界，最广泛使用的噪声模型是泊松-高斯模型（Poisson-Gaussian Noise Model）。

它的核心结论是：噪声的方差（Variance，即噪声强度的平方）与信号强度成线性关系。

噪声方差=k⋅信号强度+b \text{噪声方差} = k \cdot \text{信号强度} + b 噪声方差=k⋅信号强度+b

为什么看“方差”而不是看“均值”？

噪声的均值是 0（正负波动相互抵消），所以均值无法描述噪声的大小。而方差描述的是“波动幅度”——方差越大，说明噪声越剧烈。用公式表示：

方差=E[(x−μ)2] \text{方差} = \mathbb{E}[(x - \mu)^2] 方差=E[(x−μ)2]

即“每个像素值与其平均值的偏差的平方的平均值”。方差越大，像素越“跳”，噪点越明显。

2.3 拆解公式：k 和 b 的物理含义

符号名称物理来源随什么变化
k斜率（增益因子）光子散粒噪声 + Sensor增益（ISO）随ISO升高而增大
b截距（底噪因子）读出噪声 + 量化噪声基本固定，随ISO略有升高

直观理解：

  • 当信号强度为0（全黑图）时，噪声方差 ≠ 0，而是 = b。这就是“哪怕全黑也有噪点”的原因（读出噪声）。
  • 当信号强度为100时，噪声方差 = k×100 + b。如果k=0.001，那方差 = 0.1 + b。如果k=0.01，方差 = 1 + b。
  • k 越大，说明噪声随亮度增长得越快（高ISO下尤其明显）。

2.4 为什么叫“泊松-高斯”？

这个模型其实是将两种数学分布叠加：

  1. 泊松分布（描述光子随机到达）：方差 = 均值（信号强度），对应公式中的 k·Signal
  2. 高斯分布（描述电路热噪声）：方差为常数，对应公式中的 b

两者叠加后的总方差，就是简单的加法：k·Signal + b。

三、噪声标定 —— 如何测量 k 和 b

3.1 标定的目标

给一个具体的Sensor（如某型号传感器），我们要算出：

  1. 它的 k 和 b 是多少？
  2. 不同ISO下，k 和 b 如何变化？
  3. 图像不同位置（中心 vs 边缘）的 k 和 b 是否相同？

3.3 为什么是“时域平均”？

在标定过程中，有一个关键操作叫**“时域平均”**——同一场景拍多帧，然后对每帧做平均。

原理：噪声在时间上是随机的。对100帧同一场景取平均，噪声会被抵消掉（趋近于0），而真实信号保持不变。这样就得到了“干净图”（ground truth）。

标定公式：

Mean=1N∑i=1NFramei,Variance=1N∑i=1N(Framei−Mean)2 \text{Mean} = \frac{1}{N}\sum_{i=1}^{N} \text{Frame}_i \quad,\quad \text{Variance} = \frac{1}{N}\sum_{i=1}^{N} (\text{Frame}_i - \text{Mean})^2 Mean=N1​i=1∑N​Framei​,Variance=N1​i=1∑N​(Framei​−Mean)2

N越大，平均结果越接近真实信号，方差估计越准确。

3.4 工程细节：镜头阴影（Lens Shading）的影响

镜头中心的光线是垂直入射的，边缘是斜射的，所以图像边缘收到的光比中心少（暗角现象）。

这意味着：

  • 图像中心区域：信号强 → 噪声大（k 大）
  • 图像边缘区域：信号弱 → 噪声小（k 小）

如果不区分位置，给整张图一个统一的 k：

  • 中心区域去噪强度不足（噪声残留）
  • 边缘区域去噪过度（纹理被抹掉）

解决方案：生成与图像尺寸相同的 kmap 和 bmap，每个像素都有自己的 k 和 b 值。

四、从标定到AI训练 —— kmap/bmap如何进入模型

4.1 为什么需要kmap与bmap

核心原因：为了“省参数”和“省计算量”

盲猜（只给 x）：网络必须用第一层卷积去算“这个像素亮度是多少”，用第二层去算“周围像素亮度差异”……为了算出这个“亮度→噪声”的物理公式，网络需要浪费掉几十万个神经元来拟合那条简单的直线（方差 = k×亮度 + b）。

开卷（给 k/b）：既然已经用数学公式算好了，直接塞给网络。网络就不需要用卷积层去模拟数学公式了。省下来的神经元，可以全部用来干真正的脏活累活——区分“噪声”和“真实纹理”。

4.2 扩展视角：从“黑盒”到“灰盒”

纯学术研究的做法是“端到端黑盒”：输入带噪声图，输出干净图，模型自己学一切。

工业界的做法是“灰盒”：

  1. 物理先验：先标定出 k 和 b，把噪声的物理特性变成显式输入
  2. 数据驱动：模型只学习“如何根据 k/b 来去噪”，不学习“如何猜 k/b”

优势：

  • 模型更小（省神经元）
  • 推理更快（计算量小）
  • 泛化更强（换Sensor只需重新标定，不需重新训练模型）

4.3 在代码中：kmap 和 bmap 是“额外输入通道”

如在 multi_dataset_loader 笔记中看到的：

sample = {
    'input':  [带噪声的RAW图],   # 模型要处理的输入 x
    'target': [干净RAW图],       # 标准答案 y_true
    'kmap':   噪声参数k,         # 辅助信息，告诉模型噪声强度
    'bmap':   噪声参数b          # 辅助信息
}

模型拿到 input + kmap + bmap 后，会把它们拼接到一起（例如 4通道RAW + 1通道K + 1通道B = 6通道输入），让网络在处理每个像素时，都能参考该点的噪声强度。

五、数据集的建立 —— 业界如何处理“真实噪声”

5.1 三种主流方案

方案做法优点缺点
方案1：纯合成用 k 和 b 在干净图上直接加噪声数据无限、便宜、k/b 完全可控可能不真实，存在模型与真实Sensor的Gap
方案2：真实Pair拍摄真图 + 多帧平均得到干净图噪声最真实成本极高，只能拍静态场景，无法覆盖运动
方案3：自监督只用单张噪声图训练（如Noise2Noise）不需要干净图对低信噪比场景效果有限

5.2 工业界的常见做法：方案1为主 + 方案2验证

  • 99%的数据来自方案1：在干净的RAW图上，用标定出的 k 和 b 合成噪声
  • 1%的数据来自方案2：拍摄真实场景的Pair，用来验证模型的真实效果，防止“合成数据和真实数据之间的Gap”

5.3 为什么合成数据“可能不真实”？

标定得到的 k 和 b 是模型对噪声的近似，不是完美描述。真实Sensor可能有：

  • 坏点（Defect Pixel）：某个像素永远偏亮或偏暗
  • 条状噪声：Sensor读出电路问题导致的横向条纹
  • 温度漂移：温度变化导致 b 变化
  • 非线性响应：高亮度下 k 不再是常数

所以，标定模型越精确，合成数据越真实，模型在真实场景上表现越好。这也是你PPT中“探索进一步建模dark noise”、“直接标定kb的问题”、“2step标定k,b”等章节在讨论的内容。

关键总结

噪声建模 = 把物理世界的随机性，压缩成 k 和 b 这两个数学参数，让AI不需要自己猜“噪声长什么样”，只需要根据 k/b 去“怎么去噪”。
