YUV 色彩空间

1. 什么是 YUV

1.1 YUV 的定义

YUV 是一种色彩空间，用三个分量来表示颜色：

分量全称含义
YLuma（亮度）图像的明暗信息，即黑白灰度图
UChrominance（蓝色色度）蓝色与亮度的差值（蓝-黄轴）
VChrominance（红色色度）红色与亮度的差值（红-青轴）

术语解释：色彩空间（Color Space） 是用一组数值来描述颜色的数学模型。RGB 和 YUV 都是色彩空间，只是描述方式不同。RGB 描述“每个像素有多少红/绿/蓝”，YUV 描述“这个像素有多亮、偏蓝还是偏红”。

U 和 V 不是独立的“纯颜色”，而是颜色偏离灰色的方向。你可以把 U/V 想象成一个坐标轴：

  • U 轴（蓝-黄轴）：

    • U > 0（正数）：偏蓝
    • U < 0（负数）：偏黄
    • U = 0：没有蓝色偏移（纯灰色）

  • V 轴（红-青轴）：

    • V > 0（正数）：偏红
    • V < 0（负数）：偏青（青色是红色的补色）
    • V = 0：没有红色偏移（纯灰色）

为什么叫“蓝-黄轴”而不是“蓝轴”？ 因为 U 的值是“蓝色减去亮度（B - Y）”。如果蓝色比亮度高，U 为正，偏蓝；如果蓝色比亮度低（即红+绿占主导），U 为负，偏黄。所以这是一条从蓝到黄的连续轴，0 在中间。

1.2 RGB 和 YUV 的对比

RGBYUV
分量含义红、绿、蓝的强度亮度 + 两个色度
信息分布亮度和颜色混在一起亮度和颜色分离
人眼匹配度不匹配（三个分量同等重要）匹配（Y 最重要，U/V 不重要）
存储效率低（三个分量同等精度）高（U/V 可压缩）

1.3 YUV 的数据格式

YUV 有三个通道，每个像素位置都有一组 (Y, U, V) 值。与 RGB 的 (R, G, B) 一一对应不同，YUV 在实际编码中常对 U/V 做下采样（因为人眼对色度不敏感），但这里只在算法层面处理全分辨率的 YUV，不涉及编码压缩。

术语解释：下采样（Downsampling） 就是缩小图像的尺寸。比如一张 1920×1080 的图，下采样 2 倍后变成 960×540。

这里对 U/V 做下采样的意思是，降低 U 和 V 通道的分辨率（长和宽各缩小一半或更多），但保留 Y 通道的全分辨率。

2. 为什么需要 YUV

2.1 人眼对亮度和色度的敏感度不同

人眼视觉系统的特性：

通道人眼敏感度处理策略
Y（亮度）非常敏感需要精细处理，保留细节
U/V（色度）不敏感可以大幅降噪/压缩，人眼察觉不到

术语解释：色度（Chrominance） 是颜色的属性，区别于亮度。它描述的是“这是什么颜色”（红色、蓝色、绿色），而不是“这个颜色有多亮”。人眼对色度的分辨率远低于对亮度的分辨率——你可以看清黑白报纸上的小字，但彩色印刷稍微偏色也不太容易察觉。

2.2 分离亮度和颜色的好处

应用好处
图像压缩降低 U/V 分辨率，文件变小，人眼感觉不到
图像去噪Y 用精细算法，UV 用强力降噪，视觉效果更好
色彩调整单独调整 U/V 改变色调，不影响亮度

2.3 在去噪训练中的具体应用

训练中把图像从 RGB 转到 YUV 后，对 Y 和 U/V 使用不同的 Loss 权重：

  • Y 通道（亮度噪声最明显）：使用 SSIM Loss（保留结构）
  • UV 通道（色度噪声人眼不敏感）：使用 L1 Loss（强力降噪）

这就是在训练日志里看到的 yuv_loss——它不是一个单独的 Loss 函数，而是 Y 和 UV 分别用不同 Loss 计算后的加权和。

3. YUV 的计算（RGB → YUV 转换）

3.1 转换矩阵

RGB 到 YUV 的转换是一个线性变换，用 3×3 矩阵完成。标准 BT.601 的转换公式：

Y  =  0.299 × R + 0.587 × G + 0.114 × B
U  = -0.147 × R - 0.289 × G + 0.436 × B
V  =  0.615 × R - 0.515 × G - 0.100 × B

术语解释：BT.601 是国际电信联盟制定的标准，定义了 RGB 到 YUV（更准确地说是 YCbCr）的转换矩阵系数。它基于人眼对 RGB 三原色的敏感度（人眼对绿色最敏感，对红色次之，对蓝色最不敏感）来确定系数权重。

矩阵形式：

┌───┐   ┌                         ┐   ┌───┐
│ Y │   │  0.299   0.587   0.114  │   │ R │
│ U │ = │ -0.147  -0.289   0.436  │ × │ G │
│ V │   │  0.615  -0.515  -0.100  │   │ B │
└───┘   └                         ┘   └───┘

3.2 用具体数字走一遍

假设一个像素的 RGB 值是 (R=100, G=150, B=80)：

Y = 0.299 × 100 + 0.587 × 150 + 0.114 × 80
  = 29.9 + 88.05 + 9.12 = 127.07

U = -0.147 × 100 - 0.289 × 150 + 0.436 × 80
  = -14.7 - 43.35 + 34.88 = -23.17

V = 0.615 × 100 - 0.515 × 150 - 0.100 × 80
  = 61.5 - 77.25 - 8 = -23.75

Y = 127 表示这个像素的亮度在中间值（0~255 范围）附近。U = -23 和 V = -24 都是负数，表示这个颜色偏黄绿色（因为 R 和 B 都低于 G）。

3.3 YUV → RGB 的逆转换

R = Y + 1.140 × V
G = Y - 0.395 × U - 0.581 × V
B = Y + 2.032 × U

这两个转换是一对精确的逆操作。只要知道转换矩阵，就可以无损地在 RGB 和 YUV 之间来回切换。

4. 代码中的 YUV

4.1 YUV Loss 的实现

完整的 ISP 模拟链路：BLC → AWB → Demosaic → CCM → Gamma → RGB2YUV。

核心的 RGB → YUV 转换代码：

# loss/yuv_loss.py（概念简化）
class RGB2YUV(nn.Module):
    def forward(self, rgb):
        # rgb: [B, 3, H, W]
        r, g, b = rgb[:, 0:1], rgb[:, 1:2], rgb[:, 2:3]
        y = 0.299 * r + 0.587 * g + 0.114 * b
        u = -0.147 * r - 0.289 * g + 0.436 * b
        v = 0.615 * r - 0.515 * g - 0.100 * b
        return torch.cat([y, u, v], dim=1)

4.2 YUV Loss 在训练中的使用

在训练过程中的 Loss 计算部分：

# iir_train_ops.py（概念简化）
gt0_yuv = self.raw2yuv(target_img_decomp)      # 目标图像 → YUV
output_yuv = self.raw2yuv(net_out)             # 模型输出 → YUV

# Y 通道：SSIM Loss（人眼对亮度最敏感）
y_loss = 1 - ssim(output_yuv[:, 0:1], gt0_yuv[:, 0:1])

# UV 通道：L1 Loss（人眼对色度不敏感）
uv_loss = l1_loss(output_yuv[:, 1:3], gt0_yuv[:, 1:3])

# 合并
yuv_loss = uv_loss * 10 + y_loss

为什么 UV 权重是 10？ 因为 U/V 的值域比 Y 小，需要乘以权重才能在总 Loss 中占合理比例。

5. YUV 在 AI 去噪训练中的作用

5.1 为什么不在 RAW 域直接算所有 Loss？

RAW 域是 Bayer 马赛克格式（每个像素只有一种颜色），缺少颜色信息。直接在这上面算 Loss，模型无法感知颜色是否准确。转到 YUV 后，模型才能学习到颜色相关的信息，YUV Loss 的作用就是告诉模型“去噪后的图像在颜色上也要准确”。

5.2 YUV Loss 和其他 Loss 的分工

Loss作用域优化目标
RAW L1 + SSIMRAW 域像素级重建精度
YUV LossYUV 域颜色准确性和人眼感知质量
Motion LossRAW 域运动区域去噪
Time LossRAW 域帧间一致性
YUV Loss 是唯一直接优化“颜色”的 Loss，对最终图像质量至关重要。

6. 一句话总结

YUV 把图像的亮度（Y）和颜色（U/V）分离，因为人眼对亮度更敏感，对颜色更迟钝，所以 ISP 和 AI 训练中可以区别对待——Y 通道精细处理，UV 通道强力压缩，从而在保持画质的同时节省存储和算力。在去噪训练中，YUV Loss 负责优化颜色准确性，让模型输出的图像在最终显示时色彩正确。
