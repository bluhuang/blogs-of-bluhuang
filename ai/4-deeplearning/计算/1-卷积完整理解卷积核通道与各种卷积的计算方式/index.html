卷积完整理解：卷积核、通道与各种卷积的计算方式

BluHuang 2026年8月17日 计算中 统计中

本文只讨论一个核心问题：

一个卷积层到底怎样在空间和通道两个维度上做计算？

1 先统一最容易混乱的三个概念

1.1 Input Channel

假设输入：

3 × H × W

表示有 3 张 feature map：

Input Ch0
Input Ch1
Input Ch2

RGB 图像就是最直观的例子：

R
G
B

网络内部也一样，只不过这些 Channel 不再有明确的“红绿蓝”含义，而是模型自己学习出的 Feature。

1.2 二维 Kernel

一个最普通的 3×3 kernel 就是 9 个权重：

□ □ □
□ □ □
□ □ □

它在某一个输入 Channel上滑动，计算局部加权和。

因此：

如果只讨论一张输入 feature map，那么一个二维 Kernel 就处理一个 Channel。

1.3 Filter：产生一个 Output Channel 所需的整组 Kernel

关键就在这里。

假设输入有 3 个 Channel：

Ch0
Ch1
Ch2

想得到 1 个 Output Channel。

普通卷积并不是只挑一个输入 Channel，而是：

Input Ch0 ── Kernel0 ──┐
                       │
Input Ch1 ── Kernel1 ──┼── 相加 + bias ──> Output Ch0
                       │
Input Ch2 ── Kernel2 ──┘

也就是说：

一个输出 Channel
=
3 个输入 Channel 各做一次卷积
+
三个结果相加
+
bias

所以可以统一术语：

二维 Kernel
= 某个输入 Channel 上的一张 K×K 权重

Filter
= 为产生一个 Output Channel 而准备的一整组 Kernel

如果：

Cin = 3
kernel = 3×3

那么一个普通 Filter 实际大小是：

3 × 3 × 3
↑   ↑   ↑
Cin H   W

2 普通卷积到底怎么算

来看：

nn.Conv2d(
    in_channels=3,
    out_channels=2,
    kernel_size=3
)

输入：

3 × H × W

输出：

2 × H' × W'

为什么输出是 2 Channel？

因为：

out_channels = 2

表示网络准备了 两组 Filter，输出2个通道（每个Filter是3个3x3卷积）。

2.1 Output Channel 0

Input Ch0 ── K00 ──┐
                   │
Input Ch1 ── K01 ──┼── SUM ──> Output Ch0
                   │
Input Ch2 ── K02 ──┘

2.2 Output Channel 1

它使用另一整套权重：

Input Ch0 ── K10 ──┐
                   │
Input Ch1 ── K11 ──┼── SUM ──> Output Ch1
                   │
Input Ch2 ── K12 ──┘

所以总共有：

2 个 Output Channel
×
3 个 Input Channel
=
6 张二维 3×3 Kernel

PyTorch 权重 Shape：

[Cout, Cin, Kh, Kw]

= [2, 3, 3, 3]

2.3 “32 个卷积核产生 32 个 Channel”是什么意思?

比如：

nn.Conv2d(
    11,
    32,
    kernel_size=2
)

我们平时会简化说：

有 32 个卷积核，所以产生 32 个输出 Channel。

这个说法方便，但不够准确。

准确说应该是：

有 32 个 Output Filter，因此产生 32 个 Output Channel。

而每一个 Filter 都包含：

11 张 2×2 Kernel

所以权重 Shape：

[32, 11, 2, 2]

3 通道数量到底是怎么增加的

例如：

Conv2d(
    in_channels=11,
    out_channels=32,
    kernel_size=2
)

就是：

11 Input Channels
        ↓
准备 32 组不同 Filter
        ↓
得到 32 个不同 Output Channels

所以：

输出 Channel 数由 out_channels 决定。

例如：

11 → 32

就是设置：

out_channels=32

再比如：

32 → 48

就是：

out_channels=48

每个新的 Output Channel 都有自己独立的一套权重，所以可以学习不同的 Feature 表示。

最实用的记忆：

in_channels
→ 这一层读取多少个输入 Channel

out_channels
→ 这一层生成多少个输出 Channel

kernel_size
→ 空间上一次看多大的区域

stride
→ 空间上每次走多远

4 Group Conv：改变的不是 Kernel 大小，而是 Channel 连接关系

现在进入 Group Conv。

假设：

Cin = 4
Cout = 4

先看普通卷积。

4.1 普通 Conv：每个 Output 都读取全部 Input

            ┌──── O0
I0 ─────────┤
I1 ─────────┤
I2 ─────────┤
I3 ─────────┘


            ┌──── O1
I0 ─────────┤
I1 ─────────┤
I2 ─────────┤
I3 ─────────┘

...

也就是说：

O0 ← I0,I1,I2,I3
O1 ← I0,I1,I2,I3
O2 ← I0,I1,I2,I3
O3 ← I0,I1,I2,I3

Channel 是全连接的。

4.2 Group Conv：先把 Channel 切组

设置：

groups=2

那么：

Input:

Group 0
I0 I1

Group 1
I2 I3

Output 也分为两组：

Group 0
O0 O1

Group 1
O2 O3

连接变成：

Group 0：

I0 ─┬── O0
I1 ─┘

I0 ─┬── O1
I1 ─┘


Group 1：

I2 ─┬── O2
I3 ─┘

I2 ─┬── O3
I3 ─┘

因此：

O0/O1 只能看到 I0/I1

O2/O3 只能看到 I2/I3

这就是 Group Conv 的本质：

不是改变二维 Kernel 怎么滑，而是限制每个 Output Channel 可以连接哪些 Input Channel。

5 Group Conv 为什么省计算

假设：

Cin = 32
Cout = 32
groups = 2

普通卷积中，一个 Output Filter 要读取：

32 个 Input Channels

Group Conv 中，假设group = 2，一个 Output Filter 只需要读取：

32 / 2 = 16

个 Input Channels。

因此大致只需要一半的 Channel 计算。

如果：

groups = 4

则每个 Output 只读取：

32 / 4 = 8

个 Input Channels。

所以：

Group 越多，每个 Output 能看到的 Input Channel 越少，计算越便宜。

PyTorch 中 Group Conv 的权重 Shape：

[Cout, Cin/groups, Kh, Kw]

例如：

Cin=32
Cout=32
groups=2
kernel=3×3

权重 Shape：

[32, 16, 3, 3]

而普通卷积是：

[32, 32, 3, 3]

这就是参数和计算减少的原因。

6 Group Conv 的代价：Group 之间失去交流

还是：

Group 0：I0~I15
Group 1：I16~I31

Group Conv 以后：

Output 0~15
永远没看过 Input 16~31

Output 16~31
永远没看过 Input 0~15

于是产生一个问题：

为了省计算，把 Channel 人为隔离了。

这就是为什么很多高效网络不会只使用 Group Conv。

7 Pointwise Conv：用 1×1 把 Channel 再混回来

Group Conv
↓
1×1 Conv

为什么？

因为普通 1×1 Conv：

Conv2d(
    32,
    32,
    kernel_size=1,
    groups=1
)

虽然空间上只看当前位置：

□

但 Channel 上会读取全部 32 个输入。

某个位置：

Input:
[x0,x1,x2,...,x31]

一个 Output Channel 会对这 32 个值做一次加权组合：

x0 ─┐
x1 ─┤
x2 ─┤
... ├──> Output Ch0
x31 ─┘

下一套权重再生成 Output Ch1。

所以：

1×1 Conv 不负责看周围像素，主要负责重新组合 Channel。

group后，有32个通道，这里用一个1x1的filter，每个filter是32个 1 x 1，每个输出通道都使用一个filter，对 32 个输入通道分别乘各自的权重，再求和。

7.1 以32通道，groups=2举例

例如：

32 Channel
groups=2

先：

Group 0：16ch
    ↓
Group Conv
    ↓
16ch


Group 1：16ch
    ↓
Group Conv
    ↓
16ch

两组暂时隔离。

然后：

全部32ch
   ↓
1×1 Conv
   ↓
全部32ch重新混合

完整逻辑：

32ch
 │
 ├─────────────┐
 ▼             ▼
16ch          16ch
Group0        Group1
 │             │
 ▼             ▼
Group Conv    Group Conv
 │             │
 └──────┬──────┘
        ▼
      32ch
        │
        ▼
     1×1 Conv
        │
        ▼
      32ch

所以这里的 V3 可以理解成：

空间卷积阶段先用 Group Conv 省计算，再用 1×1 Conv 恢复跨 Group 的 Channel Mixing。

8 Depthwise Conv：这才真正接近“一个通道一个空间卷积核”

假设：

Cin = 4

设置：

groups=4

也就是：

groups = Cin

那么每个 Group 只有一个输入 Channel：

I0 ── 3×3 ── O0
I1 ── 3×3 ── O1
I2 ── 3×3 ── O2
I3 ── 3×3 ── O3

这就是 Depthwise Conv。

此时权重 Shape：

[4, 1, 3, 3]

因为每个 Output 只读取一个 Input Channel。

9 普通 Conv、Group Conv、Depthwise Conv 是一条连续关系

可以统一看 groups：

groups = 1
        │
        ▼
普通 Conv
每个 Output 看全部 Input


groups 增加
        │
        ▼
Group Conv
每个 Output 只看一部分 Input


groups = Cin
        │
        ▼
Depthwise Conv
每个 Output 只看一个 Input

所以 Depthwise Conv 并不是完全独立的一种机制。

它本质上是：

Group Conv 的极端情况。

10 Depthwise Separable Conv

Depthwise 非常省计算，但有一个巨大问题：

I0 → O0
I1 → O1
I2 → O2

Channel 完全不交流。

所以通常后面再加：

1×1 Pointwise Conv

变成：

Input
 │
 ▼
Depthwise K×K
 │
 │ 每个 Channel 单独处理空间
 ▼
Feature
 │
 ▼
Pointwise 1×1
 │
 │ 所有 Channel 重新混合
 ▼
Output

这叫：

Depthwise Separable Convolution

MobileNet 中非常常见。

11 Group+Pointwise 和 Depthwise Separable Conv 有什么区别

Group Conv
+
Pointwise Conv

不是严格的：

Depthwise Conv
+
Pointwise Conv

例如 ：

32ch
groups=2

那么每个 Group 有：

16ch

也就是说空间卷积内部：

16 个 Channel 仍然可以互相组合。

Depthwise：

32ch
groups=32

每组只有：

1ch

所以可以把三种方案看成：

普通 Conv
每组32ch
计算重，Channel交流最充分

       ↓

V3 Group Conv
每组16ch
计算和表达能力折中

       ↓

Depthwise Conv
每组1ch
最便宜，空间卷积阶段完全无Channel交流

12 1×1 Conv 不只是用于 Group 后面

1×1 Conv 还有一个非常重要的用途：

改变 Channel 数量。

例如：

Conv2d(
    32,
    64,
    kernel_size=1
)

可以：

32ch → 64ch

因为有 64 个 Output Filter。

而：

Conv2d(
    64,
    16,
    kernel_size=1
)

可以：

64ch → 16ch

所以 1×1 Conv 经常承担：

Channel Mixing
Channel Expansion
Channel Reduction
Channel Projection

而不主要承担空间特征提取。

13 卷积还有另一个维度：Kernel Size

到这里要特别注意：

普通 / Group / Depthwise 描述的是 Channel 怎么连接。

而：

1×1
2×2
2×3
3×3
5×5

描述的是：

空间上一次观察多大的区域。

这是两个不同维度。

例如完全可以有：

3×3 普通 Conv
3×3 Group Conv
3×3 Depthwise Conv

也可以：

2×3 Group Conv

14 为什么会有 2×3、3×3 等不同 Kernel

Kernel 越大，一层卷积能直接观察的局部空间范围越大，但计算也更多。

例如：

2×2
□ □
□ □

4 个位置
2×3
□ □ □
□ □ □

6 个位置
3×3
□ □ □
□ □ □
□ □ □

9 个位置

所以 2×3 相比 3×3：

  • 少计算一行；

  • 仍然保留 3 列的水平观察范围。

它可以看成空间建模和计算成本之间的一种折中。

15 Stride：控制的是空间采样步长

例如：

Conv2d(
    32,
    48,
    kernel_size=2,
    stride=2
)

stride=2 表示：

kernel 每次移动两个位置

所以：

128×128
→
64×64

主要用于 Downsample。

需要注意：

Stride 和 Group 也是两个独立维度。

完全可以：

普通 Conv + stride2
Group Conv + stride2
Depthwise Conv + stride2

16 Padding：控制卷积后的空间尺寸和边界行为

例如 3×3 Conv 如果完全不 Padding：

H×W
↓
(H-2) × (W-2)

因为 kernel 无法把中心放到最边缘的位置。

如果希望：

输入 H×W
输出仍是 H×W

通常需要先 Padding。

V3 中：

2×3 Conv
+
pad [1,1,1,0]

也是这个目的：

这一层只想提取特征，不希望改变 H/W。

Padding 不决定 Channel 数，它只影响空间边界。

17 Dilated Conv：Kernel 数量没增加，但观察范围更大

普通 3×3：

x x x
x x x
x x x

Dilated Conv 可以变成：

x . x . x
. . . . .
x . x . x
. . . . .
x . x . x

真正参与计算的还是 9 个点，但它们覆盖了更大的区域。

所以 Dilated Conv 主要用于：

以较少额外参数扩大空间感受范围。

18 ConvTranspose2d：上采样是怎么计算的

Decoder 需要把 feature map 放大，例如：

16×16
↓
32×32
ConvTranspose2d(
    in_channels,
    out_channels,
    kernel_size=2,
    stride=2
)

理解它最简单的方法是：

普通卷积是“用一个 kernel 扫过输入，得到一个输出值”；ConvTranspose 则可以理解成“一个输入值通过一个 kernel，向更大的输出区域展开”。

例如一个输入：

a  b
c  d

对于其中的 a，用一个可学习的 2×2 kernel：

w1 w2
w3 w4

得到：

a·w1  a·w2
a·w3  a·w4

因为 stride=2，下一个输入值 b 的结果会向右移动 2 格：

a·w1  a·w2   b·w1  b·w2
a·w3  a·w4   b·w3  b·w4

c·w1  c·w2   d·w1  d·w2
c·w3  c·w4   d·w3  d·w4

所以：

2×2 input
↓
ConvTranspose2d(kernel=2, stride=2)
↓
4×4 output

对于实际的多通道 feature，也是同样的思想：每个输入 Channel 都通过可学习权重向 Output Channel 展开，各输入 Channel 对同一 Output Channel 的贡献再相加。

因此：

96 × 16 × 16
↓ ConvTranspose2d(96 → 48, k=2, s=2)
48 × 32 × 32

同时完成两件事：

空间：16×16 → 32×32
通道：96 → 48

所以可以把 ConvTranspose2d 记成：

用可学习的卷积权重，把低分辨率 feature 展开成更高分辨率 feature。

19 卷积其实应该从四个独立维度理解

这是整篇最重要的整理。

以后看到一个 Conv2d，不要马上问：

“它是哪种卷积？”

先分别看四件事。

① Channel 怎么连接

看：

groups

决定：

普通 Conv
Group Conv
Depthwise Conv

② 空间一次看多大

看：

kernel_size

例如：

1×1
2×3
3×3
5×5

③ 空间尺寸怎么变化

看：

stride
padding

决定：

保持尺寸
下采样

④ 要生成多少 Feature

看：

out_channels

决定：

32ch
48ch
96ch
...

所以一个真实卷积层可能同时是：

2×3 Group Conv、stride=1、保持 H/W、32→32 channel。

这些描述并不冲突，因为它们分别在描述不同维度。

例如：

Group_Conv2d(
    32,
    32,
    kernel_size=(2,3),
    groups=2
)

不要只看到：

Group Conv。

应该完整读成：

输入：32 Channel
输出：32 Channel

空间：
每次看 2×3 邻域

Channel：
分2组
每组16个输入 Channel

stride=1

    32,

应该读成：

空间：
不看邻居，只看当前位置

全部32个Channel重新混合

所以完整 Block：

      │

      │
      │ 低成本提取空间特征

      │
      ▼

      ▼

22 最容易混淆的几个问题

Q1：普通卷积是不是“一个 Channel 一个 Kernel”？

如果“Kernel”指二维 3×3 权重：

一个 Output Filter 内，确实会为每个 Input Channel 准备一张二维 Kernel。

但：

这些 Kernel 的结果最终要相加，共同产生一个 Output Channel。

因此普通 Conv 的一个 Output 能看到全部 Input Channels。

Q2：32 个 Output Channels 就等于 32 个 Kernel 吗？

口语上可以说 32 个卷积 Filter。

更准确：

32 个 Output Filters，每个 Filter 内又包含 Cin 张二维 Kernel。

Q3：Channel 数是谁决定的？

out_channels

决定输出多少 Channel。

Q4：Kernel Size 会改变 Channel 数吗？

不会直接决定。

kernel_size

主要控制空间邻域。

Q5：Group Conv 为什么便宜？

因为每个 Output 不再读取全部 Input Channels，而只读取自己 Group 内的一部分。

Q6：Group Conv 最大的问题是什么？

不同 Group 之间缺少直接信息交流。

Q7：为什么后面接 1×1 Conv？

因为它可以在很低的空间成本下重新混合所有 Channel。

Q8：Depthwise 和 Group Conv 什么关系？

Depthwise 就是：

groups = Cin

时的特殊 Group Conv。

最后只记两条主线

第一条：空间关系

kernel_size
→ 看多大区域

stride
→ 每次走多远

padding
→ 边界怎么补、尺寸怎么保持

第二条：Channel 关系

out_channels
→ 生成多少 Feature

groups
→ 每个 Output 能连接多少 Input

1×1 Conv
→ 重新混合 / 改变 Channel

把这两个维度分开以后，各种卷积就不会再混乱。

一句话总结

普通 Conv、Group Conv、Depthwise Conv 的核心区别不是二维 Kernel 会不会在一个 Channel 上计算，而是“一个 Output Channel 最终能读取多少个 Input Channel”；Kernel Size 负责空间关系，Groups 负责 Channel 连接关系。
