排列（Permutation）类题型算法复习笔记

1. 题型识别

共同特征

  • 输入通常是一个数组或数字序列。
  • 要求对元素进行重新排列，满足某种顺序（如字典序、下一个排列、所有排列、第 k 个排列等）。
  • 核心考察点往往是字典序（lexicographical order）、回溯、数学（阶乘）。

2. 核心解题套路总结：下一个排列（31 题）

三步法（经典字典序算法）

  1. 从右向左找第一个下降点 i
    找到第一对相邻的 nums[i] < nums[i+1]，记下较小数的位置 i。
    如果找不到，说明整个数组是降序，已经是最后一个排列，直接反转整个数组。

  2. 从右向左找第一个大于 nums[i] 的数 j
    在 (i+1, end) 区间从右向左扫描，找到第一个 nums[j] > nums[i]。
    交换 nums[i] 和 nums[j]。

  3. 反转 i+1 到末尾
    将 i+1 开始的后缀反转成升序。因为交换前这部分是降序，反转后变成最小的排列。

为什么这样做？（数字类比）

把排列想象成一个数，我们要让这个数变大一点，但增幅最小。

  • 先从低位（右边）找哪个位可以变大，那就是“下降点”，因为降序后缀已经最大了。
  • 把下降点的数字和右边刚好比它大的最小数交换（让高位增幅最小）。
  • 交换后把右边排成最小（升序），保证新的数正好是下一个。

边界说明：

  • 当 i < 0（整个数组降序），直接执行 reverse，返回最小排列。
  • 找下降点时用 >=，因为要找严格下降中断的点。

3.2 全排列（有重复）—— 47. Permutations II

思路：回溯 + 排序去重。当 nums[i] == nums[i-1] 且 !used[i-1] 时跳过，避免重复排列。
关键点：先对数组排序；剪枝条件 if (i > 0 && nums[i] == nums[i-1] && !used[i-1]) continue;

3.3 第 k 个排列 —— 60. Permutation Sequence

思路：阶乘数制（康托展开）。

  • 预处理阶乘数组 fact。
  • 从高位到低位确定每一位：剩余 k 个排列，分母为 (n-i-1)!，选择 k / fact 对应的数字，然后从候选集中移除。
  • 更新 k = k % fact。
    关键点：下标转换（k 从 1 开始，需减 1 为 0-based）。

3.4 特殊排列计数/构造

  • 526：回溯 + 剪枝，或状压 DP。
  • 667：数学构造，先交替填 1, n, 2, n-1,… 再填充剩余升序。

4. 举例讲解（31 题详细模拟）

示例 1：[1,3,2]

  1. 找下降点：从右向左，2<3 不成立；3<1 不成立；发现 1<3，下降点 i=0。
  2. 找稍大数：从右向左在 [3,2] 中找第一个大于 1 的，2>1，j=2。
  3. 交换：swap(nums[0], nums[2]) → [2,3,1]。
  4. 反转后缀：反转 i+1=1 到末尾 → [2,1,3]。
    结果：[2,1,3]。

示例 2：[3,2,1]（最后一个排列）

  1. 找下降点：1<2 不成立；2<3 不成立；遍历完 i=-1。
  2. 直接执行反转：reverse(nums.begin()+0, nums.end()) → [1,2,3]。
    结果：[1,2,3]。

5. 相似题目与思路迁移

556. Next Greater Element III

转化：把正整数转成字符串，问题变成找这个数字字符串的“下一个排列”。

  • 如果存在，转回 int，注意越界（> INT_MAX）返回 -1。
    统一思考：所有“下一个更大排列”问题，本质上都是字典序的下一个排列，只需把输入转换成可索引的序列，复用 31 题算法。

6. 易错点与记忆口诀

易错点正确做法
找下降点时用 > 而不是 >=一定要用 >=，因为我们要找严格小于的转折
交换后忘记反转后缀交换后后缀依然是降序，必须反转成升序
降序数组未处理当 i < 0 时，直接反转整个数组即可
在找 j 时用 nums[j] > nums[i] 但没考虑等于条件必须是 nums[j] <= nums[i] 继续向左，否则停在第一个大于的
反转边界写错反转从 i+1 开始，不是 i

记忆口诀：

“下降点，稍大数，交换后，后缀翻。”
