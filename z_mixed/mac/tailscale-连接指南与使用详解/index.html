快速参考：状态判断、冲突解决、中继问题处理。

1. 常用命令

tailscale status

tailscale ping 100.88.241.40

tailscale netcheck

tailscale down

tailscale up

sudo pkill -f Tailscale && sleep 3 && sudo tailscale up

sudo tailscale set --relay-server-port=40000

2. 状态解读

状态含义
active; direct✅ 点对点直连，速度最快
active; direct [IPv6地址]✅ IPv6 直连，也很快
idle✅ 空闲待机，有流量自动激活，无中继即正常
active; relay "hkg/lax/..."❌ 走公共中继，速度慢，需处理

3. 出现中继怎么办？

3.1 优先尝试：重启设备（最有效）

清除残留虚拟网卡和路由表，恢复 IPv6 直连。

3.2 重启后仍存在中继则依次尝试：

临时关闭所有 VPN（包括 TUN 模式），然后重启 Tailscale

sudo pkill -f Tailscale && sleep 3 && sudo tailscale up

临时关闭防火墙（测试用）

sudo /usr/libexec/ApplicationFirewall/socketfilterfw --setglobalstate off

测试完立即重新开启：

sudo /usr/libexec/ApplicationFirewall/socketfilterfw --setglobalstate on

手动清理残留的 utun 接口（针对 0~7 编号）

sudo ifconfig utun0 down && sudo ifconfig utun0 destroy

修改相关配置（需同时使用 TUN 模式时）
在配置文件中添加：

tun:
  exclude-interface:
    - Tailscale
  route-exclude-address:
    - 100.64.0.0/10

3.3 最终方案：自建对等中继（Peer Relay）

sudo tailscale set --relay-server-port=40000

然后在路由器上做端口转发（UDP 40000 → 设备内网 IP），并在后台 ACL 中授权。
之后状态会显示 via peer-relay（比公共 DERP 快）。

4. 共存经验

  • 当前环境：TUN 模式开启 + Tailscale 走 IPv6 直连 → 可共存，无需关闭其他服务
  • 若未来又出现中继，先关闭其他 VPN 再重启 Tailscale 判断是否由冲突导致
  • 最稳定组合：规则排除 Tailscale + 启用 IPv6

5. 一句话总结

tailscale status 显示 direct 或 idle（无中继）即正常；出现中继优先重启设备。
