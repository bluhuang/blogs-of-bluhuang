1. 什么是堆？

堆（Heap）是一种特殊的完全二叉树，通常用数组存储。

  • 最大堆：每个父节点的值 大于等于 其子节点的值，堆顶为最大值。
  • 最小堆：每个父节点的值 小于等于 其子节点的值，堆顶为最小值。

堆的核心操作（插入、删除）时间复杂度均为 O(log n)，获取极值为 O(1)。

2. C++ 中的使用方式

C++ 提供了两种主要方式操作堆：priority_queue 容器适配器和 std::make_heap 等算法。其中 priority_queue 最常用。

2.1 容器适配器 priority_queue

priority_queue 默认是最大堆，通过模板参数可调整为最小堆。

#include <queue>
#include <vector>
#include <functional> // for greater

// 最大堆（默认）
std::priority_queue<int> max_heap;

// 最小堆
std::priority_queue<int, std::vector<int>, std::greater<int>> min_heap;

常用方法：top(), pop(), push(), empty(), size()。

自定义比较函数（三种方式）

1. 函数对象（重载 operator()）

struct cmp {
    bool operator()(int a, int b) { return a > b; } // 最小堆
};
priority_queue<int, vector<int>, cmp> heap;

2. 函数指针 + decltype

bool cmp(int a, int b) { return a > b; }
priority_queue<int, vector<int>, decltype(&cmp)> heap(cmp);

3. Lambda 表达式（最灵活）

auto cmp = [](int a, int b) { return a > b; }; // 最小堆
priority_queue<int, vector<int>, decltype(cmp)> heap(cmp);

2.2 重点理解：decltype 是什么？为什么 lambda 需要它？

decltype 的作用

decltype 是 C++11 引入的关键字，用于获取表达式或变量的类型。它只在编译期起作用，不会实际执行表达式。

int x = 10;
decltype(x) y = 20;        // y 的类型是 int
decltype(x + 1.5) z = 30;  // z 的类型是 double

为什么 lambda 需要 decltype？

每个 lambda 表达式都有自己独一无二的匿名类型，即使两个 lambda 的代码一模一样，它们的类型也是不同的。我们无法直接写出这个类型的名字，所以必须借助 decltype 来获取它。

auto cmp = [](int a, int b) { return a > b; };
// cmp 的类型是某个编译器生成的匿名类，我们写不出它的名字
// 但可以用 decltype(cmp) 来指代这个类型

priority_queue 的第三个模板参数是比较器的类型，因此需要传入 decltype(cmp) 来告诉编译器这个堆使用什么类型的比较器。

为什么还要把 cmp 传给构造函数？

decltype(cmp) 只告诉了编译器类型，但 lambda 本身是一个对象，堆内部需要持有一个比较器对象来调用 operator()。因此必须在构造函数中把这个对象传进去：

priority_queue<int, vector<int>, decltype(cmp)> heap(cmp);
//                                                ^^^
//                                                传入比较器对象

注意：C++20 之后，如果 lambda 没有捕获任何变量（[]），它可以默认构造，此时可以不传 cmp：

// C++20 起允许无捕获 lambda 默认构造
priority_queue<int, vector<int>, decltype([](int a, int b){ return a > b; })> heap;

但为了兼容性，建议仍然显式传入 cmp。

常见误区：为什么不能直接写 auto？

模板参数必须是类型，而 auto 是变量声明时的类型推导关键字，不能用于模板参数位置。decltype(cmp) 才是正确的类型获取方式。

一句话总结记忆

decltype(cmp) 帮编译器拿到 lambda 的匿名类型，heap(cmp) 把比较器对象交给堆使用。

2.3 堆算法 std::make_heap 等（了解即可）

适用于需要在现有 vector 上直接操作堆的场景。

vector<int> v = {3,1,4,1,5};
make_heap(v.begin(), v.end());             // 默认最大堆
v.push_back(9);
push_heap(v.begin(), v.end());             // 插入后调整
pop_heap(v.begin(), v.end());              // 将堆顶移到末尾
v.pop_back();
sort_heap(v.begin(), v.end());             // 堆排序（变为升序）

3. 优缺点

优点缺点
快速获取极值（O(1)）只能直接访问堆顶元素，无法高效查找其他元素
插入和删除效率高（O(log n)）不是稳定的数据结构
适合动态数据流的维护对于无序数据需要先建堆（O(n)）
实现简单，C++ 标准库直接支持无法直接修改堆中非顶元素（需重新建堆）

4. 适合解决的 LeetCode 题型（含完整代码）

4.1 Top K 问题

LeetCode 215. 数组中的第K个最大元素

思路：维护一个大小为 K 的最小堆，遍历数组，堆顶即为第 K 大的元素。

class Solution {
public:
    int findKthLargest(vector<int>& nums, int k) {
        priority_queue<int, vector<int>, greater<int>> minHeap;
        for (int x : nums) {
            minHeap.push(x);
            if (minHeap.size() > k) {
                minHeap.pop();
            }
        }
        return minHeap.top();
    }
};

LeetCode 347. 前 K 个高频元素

思路：先用哈希表统计频率，再用大小为 K 的最小堆维护频率最高的 K 个元素。

class Solution {
public:
    vector<int> topKFrequent(vector<int>& nums, int k) {
        // 统计频率
        unordered_map<int, int> freq;
        for (int x : nums) freq[x]++;
        
        // 最小堆，按频率比较
        auto cmp = [](pair<int, int>& a, pair<int, int>& b) {
            return a.second > b.second;
        };
        priority_queue<pair<int, int>, vector<pair<int, int>>, decltype(cmp)> minHeap(cmp);
        
        for (auto& p : freq) {
            minHeap.push(p);
            if (minHeap.size() > k) {
                minHeap.pop();
            }
        }
        
        vector<int> res;
        while (!minHeap.empty()) {
            res.push_back(minHeap.top().first);
            minHeap.pop();
        }
        return res;
    }
};

4.2 多路归并

LeetCode 23. 合并 K 个升序链表

思路：将每个链表的头节点放入最小堆，每次弹出最小节点，并将其下一个节点入堆。

class Solution {
public:
    ListNode* mergeKLists(vector<ListNode*>& lists) {
        auto cmp = [](ListNode* a, ListNode* b) {
            return a->val > b->val;
        };
        priority_queue<ListNode*, vector<ListNode*>, decltype(cmp)> minHeap(cmp);
        
        // 初始化：各链表头节点入堆
        for (ListNode* head : lists) {
            if (head) minHeap.push(head);
        }
        
        ListNode dummy(0);
        ListNode* cur = &dummy;
        while (!minHeap.empty()) {
            ListNode* node = minHeap.top();
            minHeap.pop();
            cur->next = node;
            cur = cur->next;
            if (node->next) {
                minHeap.push(node->next);
            }
        }
        return dummy.next;
    }
};

4.3 数据流中的中位数

LeetCode 295. 数据流的中位数

思路：用最大堆维护较小的一半，最小堆维护较大的一半，动态平衡两个堆的大小。

class MedianFinder {
private:
    priority_queue<int> maxHeap;                            // 较小的一半（最大堆）
    priority_queue<int, vector<int>, greater<int>> minHeap; // 较大的一半（最小堆）
    
public:
    void addNum(int num) {
        maxHeap.push(num);
        minHeap.push(maxHeap.top());
        maxHeap.pop();
        // 平衡：保证 maxHeap 的大小 >= minHeap 的大小
        if (maxHeap.size() < minHeap.size()) {
            maxHeap.push(minHeap.top());
            minHeap.pop();
        }
    }
    
    double findMedian() {
        if (maxHeap.size() > minHeap.size()) {
            return maxHeap.top();
        }
        return (maxHeap.top() + minHeap.top()) / 2.0;
    }
};

4.4 任务调度 / 贪心优化

LeetCode 253. 会议室 II

思路：按开始时间排序会议，用最小堆维护会议结束时间。每次新会议时，若堆顶（最早结束时间）≤ 开始时间，则复用会议室（弹出堆顶）；无论如何都将当前会议结束时间入堆。最终堆的大小即所需会议室数。

class Solution {
public:
    int minMeetingRooms(vector<vector<int>>& intervals) {
        sort(intervals.begin(), intervals.end()); // 按开始时间排序
        priority_queue<int, vector<int>, greater<int>> minHeap;
        for (auto& i : intervals) {
            if (!minHeap.empty() && minHeap.top() <= i[0]) {
                minHeap.pop(); // 复用会议室
            }
            minHeap.push(i[1]);
        }
        return minHeap.size();
    }
};

LeetCode 621. 任务调度器

思路：统计任务频率，用最大堆维护剩余次数最多的任务。每轮处理 n+1 个时间片，从堆中取出频率最高的任务执行并减频，若仍有剩余则暂存。一轮结束后将暂存的任务重新入堆。

class Solution {
public:
    int leastInterval(vector<char>& tasks, int n) {
        unordered_map<char, int> freq;
        for (char t : tasks) freq[t]++;
        
        priority_queue<int> maxHeap;
        for (auto& p : freq) maxHeap.push(p.second);
        
        int time = 0;
        while (!maxHeap.empty()) {
            vector<int> temp;
            for (int i = 0; i <= n; ++i) {
                if (!maxHeap.empty()) {
                    int cnt = maxHeap.top();
                    maxHeap.pop();
                    if (cnt > 1) temp.push_back(cnt - 1);
                }
                time++;
                if (maxHeap.empty() && temp.empty()) break;
            }
            for (int t : temp) maxHeap.push(t);
        }
        return time;
    }
};

4.5 滑动窗口极值

LeetCode 239. 滑动窗口最大值

思路：用最大堆存储窗口内的元素及其索引，每次移动窗口时，将新元素入堆，并循环弹出堆顶不在窗口内的元素，堆顶即为当前窗口最大值。

class Solution {
public:
    vector<int> maxSlidingWindow(vector<int>& nums, int k) {
        priority_queue<pair<int, int>> maxHeap; // {值, 索引}
        vector<int> res;
        for (int i = 0; i < nums.size(); ++i) {
            maxHeap.push({nums[i], i});
            if (i >= k - 1) {
                // 弹出不在窗口内的堆顶
                while (maxHeap.top().second <= i - k) {
                    maxHeap.pop();
                }
                res.push_back(maxHeap.top().first);
            }
        }
        return res;
    }
};

5. 各题型思路对比总结

题型核心思路堆类型关键操作
Top K维护大小为 K 的堆，遍历淘汰较小/较大元素第K大→最小堆；第K小→最大堆push 后若超限则 pop
多路归并各有序序列头节点入堆，每次取最小并补充下一节点最小堆初始入堆 + 每次弹出后补充
数据流中位数用两个堆分割数据流，保持平衡较小半用最大堆，较大半用最小堆插入后平衡两个堆的大小
任务调度/贪心堆维护最早结束时间或最高频率，贪心分配资源根据需求选最大堆或最小堆动态入堆出堆，可能配合暂存数组
滑动窗口极值堆存 {值, 索引}，惰性删除过期元素求最大用最大堆，求最小用最小堆入堆后循环 pop 不在窗口内的堆顶

6. 实现原理（简要）

堆通常用 数组 模拟完全二叉树，节点索引关系（假设根为 0）：

  • 左孩子：2 * i + 1
  • 右孩子：2 * i + 2
  • 父节点：(i - 1) / 2

核心操作依赖 上浮 和 下沉：

插入（push）

  1. 将新元素添加到数组末尾。
  2. 从该位置开始 向上调整：若当前节点大于父节点（最大堆），则交换，重复直到满足堆性质。

删除堆顶（pop）

  1. 将堆顶与最后一个元素交换，然后删除最后一个元素。
  2. 从新的堆顶开始 向下调整：若当前节点小于较大子节点（最大堆），则与较大子节点交换，重复直到满足堆性质。

建堆（make_heap）：从最后一个非叶子节点开始向下调整，时间复杂度 O(n)。

比较函数决定堆类型：

  • 最大堆：std::less<T>()（默认，parent > child）
  • 最小堆：std::greater<T>()（parent < child）

7. 总结

  • C++ 中优先队列 priority_queue 是使用堆的最便捷方式，适合动态数据。
  • 堆算法更灵活，可对已有数组进行堆操作，适合需要手动控制内存的场景。
  • 堆在解决 Top K、多路归并、中位数、任务调度、滑动窗口极值 等高频 LeetCode 题中非常实用，掌握其原理与用法是算法基本功。
