贪心系列

  • BluHuang
  • Coding
  • 2026年6月4日
目录

贪心算法是一种在每一步选择中都采取当前最优决策，从而希望得到全局最优解的算法思想。它并不对所有问题都有效，但在满足“贪心选择性质”和“最优子结构”的问题中，能够以极高的效率得到正确答案。

一、贪心算法的适用特征

  1. 贪心选择性质 局部最优选择可以导致全局最优解。即无需考虑子问题的解，直接做出当前看起来最好的选择，后续问题结构与原问题相同。
  2. 最优子结构 问题的最优解包含其子问题的最优解。这是动态规划和贪心共有的性质，但贪心要求子问题独立且选择不影响后续结构（或影响可控）。
  3. 常见问题类型 · 区间调度：选择最多不重叠区间、最少点覆盖所有区间等。 · 资源分配：最小化等待时间、最大化收益等。 · 图论：最小生成树（Prim、Kruskal）、最短路径（Dijkstra）。 · 序列问题：最长递增子序列（贪心+二分）、跳跃游戏、加油站等。 · 排序后贪心：通常先将数据按某种规则排序，再顺序决策。

二、贪心算法的解题套路

  1. 确定贪心策略

· 思考方向：每一步要选择什么？是选“最小/最大”、“最早结束/最晚开始”、“价值/重量比最高”？ · 常见策略： · 按结束时间排序 → 区间调度 · 按价值/重量比排序 → 部分背包 · 按起始时间排序 → 合并区间 · 维护一个“最优结构”，如最长递增子序列中的“尽可能小的末尾值”

  1. 证明贪心正确性（笔试可简化，但需理解）

· 交换论证：假设存在一个最优解，若其中一步不满足贪心选择，通过交换相邻元素可以得到不差于原解的解。 · 归纳法：证明每一步贪心后，剩余问题与原问题同构，且原问题的最优解可由贪心解扩展得到。

  1. 实现技巧

· 排序：大多数贪心题需要先排序。 · 数据结构优化： · 堆（优先队列）用于动态取最小/最大。 · 平衡树 / 二分查找 用于维护有序序列。 · 双指针 / 单调栈 等辅助。

三、典型案例：最长递增子序列（LIS）的贪心+二分

  1. 问题

给定一个未排序的整数数组，求最长严格递增子序列的长度。

  1. 贪心思路

· 维护一个数组 tails，其中 tails[i] 表示长度为 i+1 的递增子序列的最小末尾元素。 · 遍历原数组每个数 x： · 若 x 大于 tails 中所有数，则追加到末尾，长度增加。 · 否则，用二分查找找到第一个 tails[i] >= x 的位置，并用 x 替换它。 · 最终 tails 的长度即为 LIS 长度。

  1. 贪心选择性质解释

· 对于相同长度的递增子序列，我们只关心最小的末尾元素，因为末尾越小，后续元素越容易接在后面形成更长的序列。 · 每次用当前数替换掉第一个不小于它的末尾，就是“用当前数去优化某个长度的最小末尾”，这是一种局部最优策略，最终得到全局最长长度。

  1. 为什么是贪心？

· 每一步都在维护一组“最有潜力”的末尾值，并不需要回溯或枚举所有子序列。 · 局部最优（使每个长度的末尾尽可能小）累积成全局最优（最长长度）。

四、贪心+二分模式识别

这类题目通常具有以下特征：

  1. 需要在序列中维护一个有序结构，并且对每个元素进行“定位插入”或“替换”操作。
  2. 问题可以转化为：在某种约束下，最大化/最小化某个指标，而约束条件允许我们只保留“最有可能”的候选。
  3. 典型例题： · 最长递增子序列（贪心+二分，O(n log n)） · 俄罗斯套娃信封问题（先按宽排序，高求 LIS） · 使数组递增的最小操作数（如保留最长非递减子序列） · 最小递增子序列长度（变形）

识别关键：

· 题目要求序列中的某种顺序约束（递增、递减、非降等）。 · 常规 DP 为 O(n²)，数据范围较大时（1e5），应考虑贪心+二分。 · 思考能否通过“维护一个最优候选集”来简化问题。

五、贪心算法的局限与对比

· 贪心 vs 动态规划 贪心是动态规划的一种特例，当子问题无后效性且局部最优能导出全局最优时，贪心更高效。若不确定，可先思考 DP 再优化为贪心。 · 贪心不能解决的问题 例如 0-1 背包、最短路径中存在负权边（Dijkstra 失效）等，贪心会出错。

六、小结：贪心题解题步骤

  1. 分析问题是否具有最优子结构。
  2. 提出贪心策略（通常基于排序、极值、某种顺序）。
  3. 尝试用交换论证或归纳法证明策略正确性。
  4. 选择合适的数据结构实现（排序、堆、二分查找、平衡树等）。
  5. 编写代码并测试边界情况。

对于“贪心+二分”这类题目，核心在于维护一个有序序列，并不断用当前元素更新该序列中符合条件的位置，以达到全局最优。
